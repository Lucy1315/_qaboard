# Phase 0 — Research: QANOW

**Date**: 2026-08-29 | **Plan**: [plan.md](./plan.md)

Technical Context에서 확정이 필요했던 항목과 결론이다. 각 항목은 `결정 / 근거 / 반려한 대안` 형식이다.

## R1. 별도 백엔드 없이 헌장 원칙 II를 만족하는 방법

- **결정**: Postgres RLS를 "데이터 계층"으로 삼는다. 정책 12개를 `contracts/rls.md`에 계약으로 고정하고,
  UI를 거치지 않는 직접 호출로 검증한다.
- **근거**: 원칙 II는 "UI 숨김이 아니라 데이터 접근 계층에서 최종 강제"를 요구한다. 서버가 없는 구조에서
  이를 만족하는 지점은 데이터베이스뿐이다.
- **반려**: Supabase Edge Functions로 API 계층을 만드는 안 — 계층이 하나 늘고 RLS도 여전히 필요하다(원칙 XI).
  클라이언트 검사만 두는 안 — 원칙 II 정면 위반.

## R2. 답변 상태(`답변 대기`/`답변 완료`)를 어디에 두는가

- **결정**: 컬럼을 만들지 않고 `answers` 존재 여부에서 도출한다. 목록은 PostgREST 임베딩
  `select=id,title,created_at,author_id,answers(id)` 한 번으로 가져오고 `toQuestionSummary()`에서 계산한다.
- **근거**: 상태 컬럼을 두면 답변 등록·삭제와 동기화하는 트리거가 필요해지고 불일치 가능성이 생긴다.
  FR-006은 상태의 의미만 정의하며 저장 방식을 요구하지 않는다.
- **반려**: `questions.status` 컬럼 + 트리거 — 동기화 지점이 늘어난다(원칙 XI).
  `security_invoker` 뷰 — RLS와 뷰 권한을 함께 관리해야 해 검증 대상이 늘어난다.

## R3. 상태 필터를 서버에서 거를 것인가

- **결정**: 클라이언트에서 좁힌다.
- **근거**: 페이지네이션이 범위 밖(FR-040)이라 목록 전체를 어차피 받아온다. 서버 필터를 넣어도 요청 수만
  늘고 이득이 없다.
- **반려**: `.eq()` 서버 필터 — R2에서 상태 컬럼을 두지 않기로 했으므로 서버에서 걸 대상이 없다.
- **주의**: 이 기능 자체가 spec.md에 FR이 없다. `FR-041` 승인 전까지 구현을 차단한다.

## R4. 역할을 세션 토큰에 담을 것인가

- **결정**: 담지 않는다. `profiles.role`을 세션 확립 후 1회 조회해 React Context에 둔다.
- **근거**: 클라이언트 역할은 화면 분기용이며 권한 근거가 아니다. 서버 판정은 정책 안의 `is_admin()`이
  매 요청 다시 수행한다. 커스텀 클레임은 Auth Hook 설정과 토큰 회전 문제를 추가한다(원칙 XI).
- **반려**: JWT 커스텀 클레임 — 설정 표면이 늘고, 역할 변경이 토큰 만료까지 반영되지 않는다.

## R5. `is_admin()`의 재귀 문제

- **결정**: `SECURITY DEFINER` + `SET search_path = public`인 `stable` 함수로 감싼다.
- **근거**: 정책 조건에서 `profiles`를 직접 조회하면 `profiles`의 RLS가 다시 평가되어 무한 재귀가 난다.
- **반려**: `profiles`에 RLS를 끄는 안 — 다른 회원의 이메일이 노출된다(FR-021).

## R6. 한국어 웹폰트

- **결정**: `Gothic A1`(본문·제목)과 `IBM Plex Mono`(워드마크·숫자)를 쓴다.
- **근거**: **`IBM Plex Sans KR`은 Google Fonts에서 latin/latin-ext 서브셋만 제공하며 한글 서브셋이
  없다**(2026-08-29 확인). 한글이 시스템 폰트로 대체되어 타이포 규격이 무너진다. 한글 서브셋 파일 자체는
  정상 제공된다(예: 17KB, HTTP 200).
- **반려**: `Noto Sans KR` — 기본값 인상이 강하다. 로컬 폰트만 사용 — OS별 렌더 편차가 크다.
- **미해소**: 실제 브라우저에서 로딩 확인이 남아 있다(plan.md 미결 4번).

## R7. 대비 검증 방법

- **결정**: `tokens.css`를 읽어 대비를 계산하는 스크립트를 만들고 `npm run verify`에 넣는다.
- **근거**: 이 저장소의 과거 사례에서 보조 텍스트 대비가 4.45:1(기준 4.5:1)이었는데 육안·시안 대조·시각
  회귀 스크린샷 24장을 전부 통과하고 자동 검사에서만 걸렸다. **대비는 계산해야 안다.**
- **반려**: 시각 회귀 스크린샷만 두는 안 — 위 사례가 실패를 증명한다.

## R8. 환경 변수 검증

- **결정**: `lib/env.ts`가 **존재 + 비어 있지 않음**을 함께 검사하고, 실패 시 읽을 수 있는 오류 화면을 렌더한다.
- **근거**: 배포 플랫폼은 값 없이 만든 환경 변수를 **빈 문자열**로 주입한다. `x ?? '기본값'`이 동작하지 않아
  앱이 로드 시점에 죽고 흰 화면이 된다.
- **반려**: `??` 기본값만 두는 안 — 위 이유로 실패한다.

## R9. 테스트 계정 도메인

- **결정**: Mock/단위 픽스처는 `@example.com`을 쓰되, **Supabase 연결 단계의 실계정 시드에는 쓰지 않는다.**
- **근거**: 호스티드 Supabase Auth는 `@example.com` 같은 테스트 도메인 가입을 거부한다.

## R10. 관리자 계정 생성 경로

- **결정**: 화면으로 만들 수 없다. 일반 가입 후 `service_role` SQL로 `role='admin'` 승격.
- **근거**: FR-004. `profiles`에 UPDATE 정책을 만들지 않으면 RLS 아래에서 사용자가 자기 역할을 바꿀 수 없다.
