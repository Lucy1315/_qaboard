# QANOW 화면 설계 지시서 (Design Brief)

**대상**: Claude Design 시안 작업
**작성일**: 2026-08-29
**근거 문서**: `.specify/memory/constitution.md`(헌장 v1.0.0), `specs/001-qanow-qa-board/spec.md`(FR-001~FR-040)
**범위**: 시각 방향과 화면 설계 지시. 구현 코드(React·CSS)는 이 문서의 대상이 아니다.

## 0. 이 문서를 읽는 방법

- 본 문서는 명세를 시각 언어로 옮긴 것이며, 명세를 넘어서는 기능을 추가할 권한이 없다(헌장 원칙 IV).
  화면에 그려진 요소는 모두 spec.md의 기능 요구사항(FR) 하나 이상에 대응해야 한다.
- 각 지시에는 근거가 되는 FR 또는 헌장 원칙 번호를 병기했다(헌장 원칙 XII 추적성).
- **미결 결정**: `/speckit-clarify`에서 제기한 다음 다섯 항목은 아직 확정되지 않았다. 시안은 이 항목들에
  대해 **새 기능을 만들어 답하지 말고**, 아래 지정한 잠정 처리를 따른다.

  | 미결 항목 | 시안에서의 잠정 처리 |
  |---|---|
  | 작성·상세·수정 화면을 별도 주소로 나눌지 | 세 상태를 **같은 레이아웃의 세 가지 상태**로 그린다. 주소 구조는 시안의 관심사가 아니다 |
  | 답변 대기·완료 필터 제공 여부 | **그리지 않는다.** 명세에 없는 기능이다(FR-040 인접 범위) |
  | 회원가입 필드 구성 | 명세대로 **이메일·비밀번호만**. 닉네임·프로필 이미지를 만들지 않는다(FR-001) |
  | 비회원 CTA 선택 시 표현 방식 | "로그인 안내"로 이동하는 것만 표현한다(FR-034). 모달·인라인 여부는 미정으로 둔다 |
  | 모바일 내비게이션 구성 | 아래 17절의 지시를 따른다(항목 수가 적어 접이식 메뉴를 쓰지 않는다) |

## 1. 프로젝트와 사용자 요약

QANOW는 회원이 질문을 남기고 관리자가 답변하는 **비공개 1:1 질의응답 게시판**이다. 공개 커뮤니티가
아니다. 질문은 작성자 본인과 관리자에게만 보이며(FR-009), 다른 회원에게는 존재조차 드러나지 않는다(FR-021).

| 사용자 | 상태 | 화면에서 할 수 있는 일 |
|---|---|---|
| 비회원 | 로그인하지 않음 | 메인 페이지 열람. 보호된 화면 접근 시 로그인 안내(FR-020) |
| 회원 | 로그인함 | 질문 작성, 자기 질문 목록·상세 확인, 답변 전 수정·삭제, 답변 확인(FR-005~FR-011) |
| 관리자 | 로그인함(사전 지정 계정) | 전체 질문 목록·상세 확인, 답변 작성·수정(FR-008, FR-014, FR-015) |

핵심 흐름은 **질문 작성 → 관리자 확인 → 답변 확인** 3단계이며, 이 문장은 메인 페이지에 그대로
노출된다(FR-033).

## 2. 디자인 목표

1. **첫 화면에서 서비스를 이해시킨다.** 메인을 처음 본 사람의 90% 이상이 3단계 흐름을 설명할 수 있어야
   한다(SC-002).
2. **질문을 남기는 심리적 문턱을 낮춘다.** 가입부터 첫 질문 등록까지 3분 이내(SC-001).
3. **관리자의 작업 효율을 높인다.** 답변이 필요한 질문을 목록에서 30초 이내에 찾을 수 있어야 한다(SC-003).
   필터를 만들지 않고, **상태 표시의 시각적 우선순위**로 이 목표를 달성한다.
4. **상태를 오해 없이 전달한다.** 회원이 자기 질문 상태를 5초 이내에 식별한다(SC-004).
5. **효과가 내용을 가리지 않는다.** 메인의 시각 효과를 모두 제거해도 소개·흐름·CTA는 동일하게 읽히고
   동작해야 한다(FR-035, 헌장 원칙 VI).
6. **세 화면이 한 서비스로 읽힌다.** 같은 의미의 요소는 세 화면에서 같은 용어·같은 모양(FR-039, 원칙 V).

## 3. 브랜드 키워드

**핵심 3어**: 명확함(Clarity) · 신뢰(Trust) · 신속함(Responsiveness)

- **명확함**: 질문과 답변이 뒤섞이지 않고 시각적으로 분리된다. 상태는 언제나 글자로 읽힌다.
- **신뢰**: 과장 없는 정보 밀도, 절제된 장식, 계산된 대비. "답변이 온다"는 확신을 주는 정돈된 인상.
- **신속함**: 가볍고 빠른 화면. 효과보다 내용이 먼저 표시된다.

**톤**: 기술적으로 정교하되 차갑지 않다. 전문 서비스의 단정함 쪽이며, 소비재의 발랄함이나 SaaS 랜딩의
과장된 미래감 쪽이 아니다.

## 4. 핵심 화면 3개의 목적

| 화면 | 한 문장 목적 | 성공 판정 |
|---|---|---|
| **메인 페이지** | 처음 온 사람이 QANOW가 무엇인지 이해하고 질문 작성으로 진입하게 한다 | 3단계 흐름을 안내 없이 설명할 수 있다(SC-002) |
| **질문 리스트 페이지** | 회원에게는 내 질문의 처리 상태를, 관리자에게는 답변할 질문을 즉시 파악하게 한다 | 상태 식별 5초, 답변 대상 탐색 30초(SC-003·SC-004) |
| **질문 페이지** | 질문을 쓰고, 질문과 답변 전체를 한 화면에서 확인하고, 허용된 편집을 수행하게 한다 | 질문과 답변을 스크롤 외 조작 없이 함께 확인(SC-011) |

**비목표**(그리지 않을 것): 메인에 질문 목록·내용 노출 금지. 리스트에 검색·정렬 변경·페이지네이션 금지.
질문 페이지에 첨부·댓글 금지(FR-040).

## 5. 화면별 정보 우선순위

시선이 닿아야 하는 순서이다. 위에 있을수록 크고, 진하고, 먼저 보여야 한다.

**메인 페이지**
1. 메인 문구(무엇을 해 주는 서비스인가)
2. 주요 CTA "질문 작성하기"
3. 보조 문구(한 문장 설명)
4. 3단계 이용 흐름
5. 보조 CTA "내 질문 확인하기"
6. 헤더 내비게이션·로그인 상태
7. 배경 시각 효과 ← **가장 낮다. 어떤 경우에도 1~5를 가리지 않는다**

**질문 리스트 페이지**
1. **답변 상태 배지** (관리자에게는 답변 대기가 가장 먼저 보여야 한다)
2. 질문 제목
3. 작성 시각
4. (관리자 전용) 작성자 식별값
5. 화면 제목과 목록의 성격("내 질문" / "전체 질문")
6. 질문 작성 진입 수단(회원)

**질문 페이지**
1. 질문 제목
2. 답변 상태 배지
3. 질문 본문
4. **답변 본문**(있는 경우, 질문과 시각적으로 분리)
5. 허용된 행동 버튼(수정·삭제 또는 답변 작성·수정)
6. 작성 시각·수정 시각
7. 목록으로 돌아가는 수단

## 6. 화면별 필수 콘텐츠

**메인 페이지** (FR-033, FR-034)
- 헤더: 서비스 이름 QANOW, 내비게이션, 로그인 상태에 따른 진입 수단
- Hero: 메인 문구, 보조 문구, 주요 CTA, 보조 CTA
- 이용 흐름: 3단계를 순서가 보이는 형태로. 각 단계에 제목과 한 줄 설명
- 서비스 소개: 비공개 1:1 응답이라는 성격을 알리는 짧은 단락
- 푸터: 서비스 이름과 최소한의 정보

**질문 리스트 페이지** (FR-007, FR-008, FR-029)
- 화면 제목과 목록 성격 설명
- 목록 항목: 제목 / 상태 배지 / 작성 시각 (관리자에게는 작성자 식별값 추가)
- 회원용 질문 작성 진입 수단
- 다섯 가지 상태 표현(16절)

**질문 페이지** (FR-005, FR-009, FR-023~FR-026)
- 작성·수정 상태: 제목 입력, 내용 입력, 각 필드의 글자 수 표시(제목 0/100, 내용 0/5000), 필드별 오류
  메시지 영역, 저장·취소
- 상세 상태: 제목, 상태 배지, 작성 시각, 질문 본문, 답변 영역(답변 본문·답변 시각), 허용된 행동
- 답변 없음일 때: 답변 영역에 "아직 답변이 등록되지 않았습니다" 안내(관리자에게는 답변 입력 영역)
- 삭제 확인 단계(FR-011): 되돌릴 수 없음을 알리는 문구와 확인·취소

## 7. 화면별 주요 CTA

| 화면 | 주요 CTA(강조 1개) | 보조 CTA |
|---|---|---|
| 메인 | **질문 작성하기** | 내 질문 확인하기 |
| 질문 리스트(회원) | **질문 작성하기** | — |
| 질문 리스트(관리자) | 없음(목록 항목 자체가 진입점) | — |
| 질문 페이지 - 작성/수정 | **등록하기 / 저장하기** | 취소 |
| 질문 페이지 - 상세(작성자, 답변 전) | 수정하기 | 삭제하기(파괴적 스타일) |
| 질문 페이지 - 상세(관리자, 답변 전) | **답변 작성하기** | — |
| 질문 페이지 - 상세(관리자, 답변 후) | 답변 수정하기 | — |

**규칙**: 한 화면에 강조(solid) 버튼은 하나만 둔다. 삭제는 파괴적 행동 스타일을 쓰되 붉은 solid 버튼으로
크게 만들지 않는다(오조작 방지).

## 8. 회원과 관리자 상태 차이

같은 화면이 역할에 따라 달라지는 지점이다. **역할 전용 화면을 새로 만들지 않는다**(원칙 XI).

| 지점 | 비회원 | 회원 | 관리자 |
|---|---|---|---|
| 메인 CTA 동작 | 로그인 안내로 이동 | 질문 작성 화면 | 질문 리스트 |
| 리스트 접근 | 로그인 안내(FR-020) | 내 질문만(FR-007) | 전체 질문(FR-008) |
| 리스트 항목 구성 | — | 제목·상태·작성 시각 | + 작성자 식별값 |
| 상세 접근 | 로그인 안내 | 본인 질문만, 타인 것은 "권한 없음" | 모든 질문 |
| 질문 편집 | — | 답변 전에만 수정·삭제 | 불가(명세에 없음) |
| 답변 영역 | — | **읽기 전용**. 입력 수단이 화면에 존재하지 않음(FR-017) | 작성·수정 |

**시각 처리**: 역할 차이는 **요소의 존재/부재**로 표현한다. 회원 화면에 답변 입력창을 흐리게(disabled)
띄워 두지 않는다. 권한이 없으면 그리지 않는다.

**작성자 식별값**: 명세가 보유한 사용자 식별 정보는 이메일뿐이다(FR-001, Key Entities). 관리자 목록에는
이메일을 쓰되, 목록에서는 길이를 제한해 표시한다. 닉네임·아바타를 발명하지 않는다.

## 9. 페이지 간 이동 구조

```
                  ┌──────────────────────────────┐
                  │        메인 페이지            │
                  │  질문 작성하기 / 내 질문 확인 │
                  └───────┬──────────────┬───────┘
        (비회원)          │              │
    로그인 안내 ←─────────┘              │
        │                                │
        ↓ 로그인·회원가입                 ↓
  ┌───────────────┐            ┌──────────────────────┐
  │  인증 화면    │───────────→│  질문 리스트 페이지   │
  │ (로그인/가입) │            │  회원: 내 질문        │
  └───────────────┘            │  관리자: 전체 질문    │
                               └──────┬───────────────┘
                          목록 항목 선택 │  ↑ 목록으로
                                        ↓  │
                               ┌──────────────────────┐
                               │     질문 페이지       │
                               │  작성 / 상세 / 수정   │
                               └──────────────────────┘
```

- 모든 내부 화면에서 **한 번의 조작으로 리스트로 돌아갈 수 있어야 한다**. 브라우저 뒤로가기에 의존하지
  않는다.
- 저장·삭제 완료 후에는 결과가 반영된 화면으로 이동하며, 사용자가 새로고침할 필요가 없다(SC-010).
- 인증 화면은 명세의 세 핵심 화면에 속하지 않으나 FR-001·FR-002가 요구한다. **세 화면과 같은 헤더·간격·
  버튼·입력 규칙을 그대로 쓰고 고유한 장식을 만들지 않는다.**

## 10. 콘텐츠 예시 문구

문서 본문은 문어체이지만, **화면 문구는 사용자를 향한 존댓말**로 쓴다. 시안은 아래 문구를 그대로 사용한다.

**메인 페이지**
- 메인 문구: `질문은 빠르게, 답변은 명확하게.`
- 보조 문구: `궁금한 점을 남기면 관리자가 확인하고 답변해드립니다.`
- 주요 CTA: `질문 작성하기` / 보조 CTA: `내 질문 확인하기`
- 이용 흐름 3단계:
  1. `질문 작성` — `제목과 내용을 남기면 접수됩니다.`
  2. `관리자 확인` — `담당 관리자가 질문을 확인합니다.`
  3. `답변 확인` — `답변이 등록되면 내 질문에서 바로 볼 수 있습니다.`
- 서비스 소개: `QANOW의 질문은 작성자 본인과 관리자에게만 보입니다. 다른 사용자에게 공개되지 않습니다.`

**상태 배지**
- `답변 대기` / `답변 완료`

**질문 리스트 페이지**
- 회원 화면 제목: `내 질문` / 설명: `내가 남긴 질문과 답변 상태를 확인할 수 있습니다.`
- 관리자 화면 제목: `전체 질문` / 설명: `답변이 필요한 질문을 먼저 확인해 주세요.`

**질문 페이지**
- 작성 화면 제목: `질문 작성`
- 제목 라벨: `제목` / 도움말: `100자 이내로 입력해 주세요.`
- 내용 라벨: `내용` / 도움말: `5000자 이내로 입력해 주세요.`
- 답변 라벨(관리자): `답변` / 도움말: `5000자 이내로 입력해 주세요.`
- 답변 없음: `아직 답변이 등록되지 않았습니다.`
- 답변 후 편집 차단: `답변이 등록된 질문은 수정하거나 삭제할 수 없습니다.`
- 삭제 확인: `이 질문을 삭제하시겠습니까? 삭제한 질문은 되돌릴 수 없습니다.`

**상태 문구**(16절에서 다시 정리)
- 로딩: `불러오는 중입니다.`
- 빈 목록(회원): `아직 남긴 질문이 없습니다.` + `질문 작성하기`
- 빈 목록(관리자): `등록된 질문이 없습니다.`
- 오류: `내용을 불러오지 못했습니다.` + `다시 시도`
- 권한 없음: `이 질문에 접근할 권한이 없습니다.` + `내 질문으로 이동`
- 저장 중: `저장 중입니다...`
- 로그인 안내: `로그인이 필요한 화면입니다.` + `로그인` / `회원가입`

**검증 오류**
- `제목을 입력해 주세요.` / `제목은 100자를 넘을 수 없습니다.`
- `내용을 입력해 주세요.` / `내용은 5000자를 넘을 수 없습니다.`
- `답변을 입력해 주세요.` / `답변은 5000자를 넘을 수 없습니다.`
- `이미 사용 중인 이메일입니다.`
- `이메일 또는 비밀번호가 올바르지 않습니다.` (어느 쪽이 틀렸는지 구분하지 않는다 — FR-003)

## 11. 색상 역할

**중요**: 아래 색상값은 **후보**이다. 확정 전에 모든 전경/배경 조합의 대비를 **계산해 기록**해야 한다.
육안 확인이나 시안 대조는 대비 검증의 근거가 되지 않는다(헌장 원칙 VI 검토 기준). 본문 4.5:1, 큰 글자
(24px 이상 또는 19px 이상 굵은 글자) 3:1, 비텍스트 경계·포커스 표시 3:1이 최소선이며, **4.6:1처럼 아슬한
값은 통과로 보지 않고 여유를 둔다.**

**어두운 영역 — 메인 Hero·푸터**

| 역할 | 후보값 | 용도 |
|---|---|---|
| `ink-900` 최심 배경 | `#080D1C` | Hero 바탕 |
| `ink-800` 배경 | `#0F1730` | 푸터, Hero 하단 |
| `ink-700` 표면 | `#18213F` | Hero 위 플로팅 카드 |
| `on-dark-strong` | `#F2F5FC` | 메인 문구, 헤딩 |
| `on-dark` | `#C7CFE4` | 보조 문구, 본문 |
| `on-dark-muted` | `#96A0BC` | 캡션. **본문에 쓰지 않는다** |
| `border-dark` | `rgba(255,255,255,0.10)` | 카드 경계 |

**밝은 영역 — 리스트·질문·인증 화면**

| 역할 | 후보값 | 용도 |
|---|---|---|
| `canvas` | `#F5F7FB` | 페이지 바탕 |

## 12. 타이포그래피 방향

- **한국어 본문 가독성이 최우선**이다. 장식적 서체를 쓰지 않는다.
- 서체는 한국어 산세리프 1종으로 통일한다. 웹폰트를 쓸 경우 **총 전송량 150KB 이하**로 제한하고,
  로딩 실패 시 시스템 산세리프로 자연스럽게 대체되어야 한다(원칙 VI 성능 예산).
- 숫자·영문은 같은 서체를 쓰되, 작성 시각처럼 정렬이 필요한 숫자에는 고정폭 숫자 처리를 권한다.

| 단계 | 데스크톱 | 모바일 | 용도 |
|---|---|---|---|
| Display | 48 / 1.2 / Bold | 32 / 1.25 | 메인 문구 |
| H1 | 30 / 1.3 / Bold | 24 / 1.3 | 화면 제목, 질문 상세 제목 |
| H2 | 22 / 1.4 / SemiBold | 20 / 1.4 | 섹션 제목, 목록 항목 제목 |
| Body | 16 / 1.75 / Regular | 16 / 1.7 | 질문·답변 본문, 설명 |
| Small | 14 / 1.6 | 14 / 1.6 | 도움말, 작성 시각 |
| Caption | 13 / 1.5 | 13 / 1.5 | 글자 수 표시, 배지 |

- **모바일에서도 본문과 입력 필드 글자는 16px 이상**으로 한다(입력 시 자동 확대 방지).
- 질문·답변 본문의 한 줄 길이는 **65~75자**를 넘지 않게 컨테이너 폭을 제한한다.
- 굵기는 Regular·SemiBold·Bold 세 가지만 쓴다.
- 대문자 변형, 자간을 크게 벌린 레이블, 텍스트 그라데이션을 쓰지 않는다.

## 13. 간격과 레이아웃 방향

- **4px 기본 단위**, 8px 리듬. 사용 값: 4·8·12·16·24·32·48·64·96.
- 컨테이너: 메인 최대 **1120px**, 내부 화면 최대 **960px**, 질문·답변 본문 읽기 폭 최대 **720px**.
- 좌우 여백: 모바일 20px, 태블릿 32px, 데스크톱 40px.
- 섹션 세로 간격: 데스크톱 96px, 모바일 56px.
- 메인은 **세로 흐름 4구획**으로 고정한다: 헤더 → Hero → 이용 흐름 3단계 → 소개·CTA 반복 → 푸터.
  구획 수를 늘리지 않는다(원칙 XI).
- 리스트는 **단일 열**이다. 카드 격자(2열·3열)를 쓰지 않는다. 항목당 높이를 일정하게 유지해 훑기 쉽게 한다.
- 질문 페이지는 **단일 열 세로 흐름**이다. 질문 블록과 답변 블록을 위아래로 놓고, 좌우 2단으로 나누지
  않는다(모바일과 구조가 어긋나는 것을 막기 위함이다).
- 정렬 기준선을 하나로 유지한다. 화면 안에서 좌측 정렬 기준이 두 개 이상 생기지 않게 한다.

## 14. 버튼·입력창·카드·배지 규칙

**모서리 반경** — 과도한 둥글기를 피한다.
- 버튼·입력창 `8px`, 카드·패널 `12px`, 배지 `6px`. **16px를 넘지 않는다. 알약(pill) 형태를 쓰지 않는다.**

**버튼**
- 종류는 세 가지뿐이다: `Primary`(채움), `Secondary`(1px 테두리), `Ghost`(텍스트).
- 높이: 데스크톱 44px, 모바일 48px. 터치 대상은 어떤 경우에도 **44×44px 이상**.
- 한 화면에 Primary는 하나. 삭제는 Secondary에 오류 색 글자·테두리를 쓴다(붉은 채움 버튼 금지).
- 상태 5종(기본·hover·active·focus·disabled)을 모두 정의한다. focus는 **2px 실선 + 2px 오프셋**이며,
  hover 효과가 focus 표시를 대신할 수 없다(원칙 VIII).
- 저장 중에는 버튼이 비활성 + 진행 텍스트로 바뀌고, 중복 제출이 불가능해야 한다(FR-031).

**입력창**
- **라벨은 항상 필드 위에 보인다.** 플레이스홀더를 라벨 대신 쓰지 않는다.
- 1px 테두리, 흰 배경. 포커스 시 테두리를 `primary`로 바꾸고 2px 포커스 링을 더한다.
- 도움말은 필드 아래 Small, 오류는 같은 위치에 오류 색 + **아이콘 + 문구**로 표시한다(색만으로 알리지
  않는다). 오류 시 테두리도 오류 색으로 바꾼다.
- 글자 수 표시는 필드 오른쪽 아래에 `0 / 100`, `0 / 5000` 형식으로 둔다(FR-023~FR-025).
- 내용·답변은 여러 줄 입력이며 최소 높이 데스크톱 240px, 모바일 180px.

**카드**
- 목록 항목과 질문·답변 블록에 쓴다. **1px 테두리 + 흰 배경**이 기본이고, 그림자는 아주 약하게
  (`0 1px 2px rgba(17,24,39,0.06)`) 쓰거나 쓰지 않는다. **그림자만으로 경계를 만들지 않는다.**
- 어두운 Hero 위의 플로팅 카드만 예외적으로 반투명을 허용하되, **배경 흐림(backdrop blur)은 쓰지 않고**
  불투명도 92% 이상의 단색 표면 + 1px 밝은 테두리로 만든다(과도한 Glassmorphism 금지).
- 질문 블록과 답변 블록은 **왼쪽 4px 강조 획**으로 구분한다. 질문은 중립 색, 답변은 `primary` 색.
  획만으로 구분하지 않고 각 블록에 `질문` / `관리자 답변` 레이블을 단다.

**배지**
- 구성: `점 또는 아이콘 + 텍스트`. **텍스트가 반드시 있다**(FR-030).
- 크기: 높이 24px, 좌우 8px 여백, Caption 굵기 SemiBold.
- 목록에서는 제목과 같은 줄의 오른쪽(데스크톱) 또는 제목 위(모바일)에 둔다.
- 상태는 두 가지뿐이다: `답변 대기`, `답변 완료`. 세 번째 상태를 만들지 않는다.

## 15. 메인 페이지 시각 효과 규칙

Hero 시각 효과는 **세 겹**으로 구성한다. 이 세 겹 외의 장식을 추가하지 않는다.

1. **오로라 그라데이션** — 어두운 네이비 바탕 위에 블루·바이올렛·시안 세 색의 부드러운 광원 2~3개.
   이미지가 아니라 CSS 그라데이션으로 만든다. 텍스트가 놓이는 영역 위로 밝은 광원이 오지 않게 배치하고,
   필요하면 어두운 오버레이를 덧대 **메인 문구 대비 7:1 이상**을 확보한다.
2. **미세한 그리드** — 1px 선, 불투명도 **0.06 이하**, 격자 간격 32~48px. 가장자리로 갈수록 사라지도록
   마스크를 건다. 그리드가 텍스트 뒤에서 읽힘을 방해하면 해당 영역에서 제거한다.
3. **질문·답변 플로팅 카드** — Hero 우측(데스크톱)에 질문 카드 1개와 답변 카드 1개를 위아래로 놓고,
   둘을 잇는 얇은 연결선으로 "질문 → 답변" 흐름을 표현한다. 카드 안에는 짧은 예시 문구와 상태 배지를
   넣되, **실제 질문 데이터를 흉내 낸 목록을 만들지 않는다**(메인은 질문 내용을 노출하지 않는다).

**애니메이션 한도**
- 움직이는 요소는 **최대 2종**(오로라의 느린 이동, 카드의 미세한 부유)까지.
- `transform`과 `opacity`만 애니메이션한다. 이동 거리 **8px 이하**, 주기 **8초 이상**, 부드러운 감속.
- 스크롤 연동 패럴랙스, 마우스 추적, 자동 재생 캐러셀, 타이핑 효과를 쓰지 않는다.
- 진입 애니메이션을 쓸 경우 지속 시간 **300ms 이하**, 요소당 1회, 지연 누적 200ms 이내.

**성능 예산**(원칙 VI — 계획 단계에서 수치로 확정할 것)
- Hero 시각 효과에 쓰는 자산 총합 **100KB 이하**. 배경 이미지·동영상·Lottie를 쓰지 않는다.
- 웹폰트 총 **150KB 이하**.
- **메인 문구·보조 문구·CTA는 시각 효과보다 먼저 표시된다.** 효과 로딩을 기다려 텍스트가 늦게 나타나는
  구성을 만들지 않는다.
- 효과를 전부 제거한 상태에서도 레이아웃이 무너지지 않고 같은 정보가 읽혀야 한다(FR-035).

## 16. 로딩·빈 화면·오류·권한 없음 상태

다섯 가지 상태를 **모든 해당 화면에서 텍스트로** 표시한다(FR-029). 각 상태는 아이콘·색만으로 구분되지
않으며, 회색조로 변환해도 구분이 유지되어야 한다(FR-030).

| 상태 | 표시 방식 | 문구 | 다음 행동 |
|---|---|---|---|
| **로딩** | 목록·상세 자리에 뼈대(skeleton) 또는 진행 표시 + 텍스트. 화면 전체를 가리는 오버레이 금지 | `불러오는 중입니다.` | 없음 |
| **빈 목록(회원)** | 목록 영역 안 중앙. 제목 + 한 줄 안내 + 버튼 | `아직 남긴 질문이 없습니다.` / `첫 질문을 남겨보세요.` | `질문 작성하기` |
| **빈 목록(관리자)** | 같은 형태, 버튼 없음(관리자는 질문을 작성하지 않는다) | `등록된 질문이 없습니다.` | 없음 |
| **오류** | 해당 영역 안. 오류 색 테두리 박스 + 아이콘 + 문구 + 재시도 버튼. 내부 예외 문구 노출 금지(FR-032) | `내용을 불러오지 못했습니다.` | `다시 시도` |
| **권한 없음** | 상세 화면 자리에 중립 색 박스. 질문의 존재 여부를 알 수 있는 정보를 넣지 않는다(FR-021) | `이 질문에 접근할 권한이 없습니다.` | `내 질문으로 이동` |
| **저장 중** | 버튼 자리에서 표현. 버튼 비활성 + 문구 변경 + 진행 표시 | `저장 중입니다...` | 중복 제출 차단(FR-031) |
| **로그인 필요** | 보호된 화면 자리에 안내 박스 | `로그인이 필요한 화면입니다.` | `로그인` / `회원가입` |

- 로딩 뼈대는 **실제 콘텐츠와 같은 높이**로 만들어 내용이 채워질 때 화면이 튀지 않게 한다.
- 상태 박스는 세 화면에서 같은 컴포넌트·같은 여백·같은 문장 형식을 쓴다(FR-039).

## 17. 모바일 반응형 기준

- 기준 폭: **360px**(최소 지원), 768px(태블릿), 1024px 이상(데스크톱). 브레이크포인트는 2개만 둔다.
- **가로 스크롤이 발생하면 실패로 본다**(FR-037). 긴 제목·긴 이메일은 말줄임 또는 줄바꿈으로 처리한다.
- **내비게이션**: 항목이 세 개 이하이므로 **접이식(햄버거) 메뉴를 만들지 않는다.** 상단 바에 서비스 이름과
  링크를 그대로 노출하고, 폭이 좁으면 링크를 아이콘 없는 짧은 텍스트로 줄인다. 메뉴 열기/닫기 상태와
  포커스 가두기 로직을 만들지 않는 편이 단순하고(원칙 XI) 키보드 접근에도 유리하다(원칙 VIII).
- 메인 Hero: 데스크톱은 좌측 텍스트 + 우측 플로팅 카드의 2단, 모바일은 **텍스트 → CTA → 플로팅 카드**
  순의 1단. 카드는 축소해 세로로 쌓고, 공간이 부족하면 카드 1개만 남긴다.
- 이용 흐름 3단계: 데스크톱 가로 3열, 모바일 세로 3행. 순서 번호를 유지한다.
- 목록 항목: 모바일에서는 `상태 배지 → 제목 → 작성 시각` 세로 배치. 배지를 제목 위에 둔다(상태를 먼저
  보게 하기 위함이다).
- 질문 페이지: 본문 좌우 여백 20px, 입력 필드는 폭을 꽉 채운다. 주요 행동 버튼이 화면 하단에서 잘리거나
  가려지지 않아야 한다(FR-037).
- 핵심 시나리오(회원 질문 등록, 관리자 답변)가 360px에서 끝까지 완료되어야 한다(SC-007).

## 18. 접근성과 모션 감소 기준

기준은 **WCAG 2.2 AA**이다. 시안과 접근성 기준이 충돌하면 접근성이 이긴다(헌장 개발 워크플로).

- **대비**: 본문 4.5:1, 큰 글자 3:1, 비텍스트(입력 테두리·아이콘·포커스 표시) 3:1 이상. 모든 조합을
  **계산해 표로 남긴다.** 값이 기준에 아슬하게 걸치면 통과로 보지 않는다.
- **포커스**: 모든 조작 가능 요소에 보이는 포커스 표시(2px 실선 + 2px 오프셋, 대비 3:1 이상). 포커스를
  숨기는 처리를 하지 않는다. 포커스 순서는 시각적 순서와 일치한다(FR-036).
- **키보드**: 가입·로그인·로그아웃·질문 작성·수정·삭제·답변 작성·수정 여덟 가지를 마우스 없이 완료할 수
  있어야 한다(SC-008). 삭제 확인 단계도 키보드로 취소·확정이 가능해야 한다.
- **폼**: 라벨과 입력이 연결되고, 오류는 필드와 연결되어 보조 기술에 전달된다. 오류 발생 시 첫 오류
  필드로 포커스를 옮긴다.
- **상태 전달**: 저장 중·오류 등 화면 변화가 보조 기술에 알려져야 한다. 색·아이콘만으로 상태를 전달하지
  않는다(FR-030).
- **모션 감소**: `prefers-reduced-motion: reduce`에서 **오로라 이동·카드 부유·진입 애니메이션·전환을 모두
  정지**시키고 최종 상태를 정적으로 표시한다. 애니메이션에만 담긴 정보가 있어서는 안 된다(FR-038).
  애니메이션을 정의한 모든 규칙에는 모션 감소 대응 규칙이 짝으로 있어야 한다.
- **터치 대상**: 44×44px 이상, 인접 대상 간 8px 이상 간격.
- **확대**: 200% 확대에서 내용 손실이나 가로 스크롤이 없어야 한다.

## 19. 만들지 말아야 할 디자인

**기능 범위 위반**(FR-040 — 그리는 순간 명세 위반이다)
- 검색창, 상태 필터 탭·드롭다운, 정렬 변경 컨트롤, 페이지네이션·무한 스크롤
- 파일 첨부 영역·클립 아이콘, 댓글·대댓글, 좋아요·조회수
- 소셜 로그인 버튼(구글·카카오 등), 비밀번호 재설정·이메일 인증 화면
- 통계 대시보드, 차트, 카운터 애니메이션, 관리자 전용 사이드바 메뉴
- 알림 벨, 읽음 표시, 태그·카테고리, 질문 공개 여부 토글
- 닉네임·프로필 사진·아바타(명세에 사용자 표시 이름이 없다)

**시각 클리셰**(흔한 AI 랜딩으로 보이지 않게 한다)
- 텍스트에 건 보라 그라데이션, 빛나는 테두리, 네온 글로우
- 떠다니는 3D 구체·추상 블롭, 별가루·파티클, 회전하는 궤도 그래픽
- 반투명 유리 패널을 겹겹이 쌓는 구성(과도한 Glassmorphism)
- 알약 형태의 크게 둥근 카드, 반경 20px 이상의 큰 라운드
- 가격표, 고객사 로고 띠, 후기·평점 섹션, "AI 기반" 같은 근거 없는 수식
- 타이핑 효과, 자동 재생 캐러셀, 마퀴, 스크롤 잠금 연출

**가독성·접근성 위반**
- 어두운 배경 위 흐린 회색 본문, 이미지·그라데이션 위에 직접 얹은 본문
- 색만으로 구분되는 상태 배지, 아이콘만 있는 상태 표시
- 라벨 없이 플레이스홀더만 있는 입력창
- 포커스 표시가 없거나 hover로 대체된 버튼
- 44px보다 작은 터치 대상, 모바일에서 16px 미만의 입력 글자

**구조 위반**
- 메인 페이지에 질문 목록이나 질문 내용 노출
- 회원 화면에 흐리게 처리된 답변 입력창(권한 없는 요소는 그리지 않는다)
- 세 화면이 서로 다른 헤더·버튼·배지·여백을 쓰는 구성

## 20. Claude Design 시안 평가 기준

시안은 아래 항목을 **하나씩 확인**해 통과 여부를 기록한다. 하나라도 실패하면 채택하지 않는다.

**A. 명세 정합성** (원칙 IV·XII)
- [ ] 화면의 모든 요소가 FR 하나 이상에 대응한다. 대응 없는 요소가 없다.
- [ ] 19절 "기능 범위 위반" 목록의 요소가 하나도 없다.
- [ ] 역할별 차이가 요소의 존재/부재로 표현되었다(비활성 요소로 암시하지 않았다).

**B. 정보 구조와 일관성** (원칙 V)
- [ ] 5절의 정보 우선순위가 크기·굵기·위치로 실제 구현되었다.
- [ ] 세 화면이 같은 헤더·같은 버튼 규칙·같은 배지·같은 여백 체계를 쓴다.
- [ ] 상태 용어가 세 화면에서 동일하다(`답변 대기`·`답변 완료`).

**C. 시각 효과와 성능** (원칙 VI)
- [ ] Hero 효과를 모두 제거해도 메인 문구·보조 문구·CTA·3단계 흐름이 동일하게 읽힌다.
- [ ] 움직이는 요소가 2종 이하이고, 이동 8px·주기 8초 한도를 지킨다.
- [ ] 배경 이미지·동영상을 쓰지 않았고 효과 자산이 100KB 이하이다.
- [ ] 텍스트가 효과보다 먼저 표시되는 구성이다.

**D. 대비와 접근성** (원칙 VI·VIII·IX)
- [ ] **모든 전경/배경 조합의 대비를 계산한 표가 시안에 첨부되었다.** 육안 판단은 근거가 아니다.
- [ ] 본문 4.5:1, 큰 글자 3:1, 비텍스트 3:1을 여유 있게 넘는다.
- [ ] 모든 상태가 회색조 변환 후에도 텍스트로 구분된다.
- [ ] 모든 조작 요소에 포커스 표시가 정의되어 있고 순서가 시각 순서와 같다.
- [ ] 모든 애니메이션에 모션 감소 대응이 짝으로 정의되어 있다.

**E. 반응형** (원칙 X)
- [ ] 360px에서 가로 스크롤이 없다.
- [ ] 360px에서 질문 작성과 답변 확인을 끝까지 완료할 수 있다.
- [ ] 터치 대상이 44×44px 이상이다.
- [ ] 접이식 메뉴 없이 내비게이션이 성립한다.

**F. 브랜드와 차별성**
- [ ] 19절 "시각 클리셰" 목록의 요소가 하나도 없다.
- [ ] 어두운 Hero와 밝은 내부 화면이 같은 서비스로 읽힌다(색·서체·간격 체계 공유).
- [ ] 질문 → 답변의 흐름이 Hero 시각 요소로 전달된다.

**G. 단순성** (원칙 XI)
- [ ] 메인의 세로 구획이 다섯 개 이하이다.
- [ ] 컴포넌트 종류가 필요한 만큼만 정의되었다(버튼 3종, 입력 2종, 카드 1종, 배지 1종, 상태 박스 1종).
- [ ] 같은 목적의 컴포넌트가 두 벌 존재하지 않는다.
