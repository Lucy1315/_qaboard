# Feature Specification: QANOW 질의응답 게시판

**Feature Branch**: `001-qanow-qa-board`

**Created**: 2026-08-29

**Status**: Draft

**Input**: User description: "QANOW라는 회원 질문·관리자 답변 게시판. 회원은 질문을 남기고 자신의 질문과 답변 상태를 확인하며, 관리자는 답변이 필요한 질문을 찾아 답변한다. 메인 페이지에서 서비스의 목적과 이용 흐름을 이해할 수 있어야 한다. 핵심 화면은 메인 페이지·질문 리스트 페이지·질문 페이지 세 개이며, 사용자는 비회원·회원·관리자 세 역할이다. 기술 스택과 구체적인 시각 디자인은 아직 결정하지 않는다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원이 질문을 남기고 답변 상태를 확인한다 (Priority: P1)

서비스를 처음 방문한 사람이 회원으로 가입하고 로그인한 뒤, 질문 제목과 내용을 작성해 등록한다. 등록한
질문은 자신의 질문 목록에 "답변 대기" 상태로 나타나며, 관리자가 답변하면 같은 목록에서 "답변 완료"로
바뀐 것을 확인하고 상세 화면에서 답변 내용을 읽는다.

**Why this priority**: 질문을 남기고 답변을 받는 것이 QANOW의 존재 이유이다. 이 흐름 하나만 동작해도
서비스는 최소한의 가치를 제공한다.

**Independent Test**: 신규 계정으로 가입 → 로그인 → 질문 작성 → 목록에서 "답변 대기" 확인 →
(사전 준비된 관리자 답변 반영 후) 상세에서 답변 확인까지 다른 스토리 없이 수행할 수 있다.

**Acceptance Scenarios**:

1. **Given** 등록되지 않은 이메일을 가진 방문자가 회원가입 화면에 있을 때, **When** 유효한 이메일과
   비밀번호를 입력하고 가입을 요청하면, **Then** 계정이 생성되고 로그인 상태가 되거나 로그인 화면으로
   안내된다.
2. **Given** 이미 사용 중인 이메일을 입력했을 때, **When** 가입을 요청하면, **Then** 계정은 생성되지
   않고 "이미 사용 중인 이메일이다"는 취지의 오류가 해당 필드에 표시된다.
3. **Given** 로그인한 회원이 질문 작성 화면에 있을 때, **When** 제목과 내용을 규칙에 맞게 입력하고
   등록하면, **Then** 질문이 저장되고 상태가 "답변 대기"로 표시된다.
4. **Given** 질문을 등록한 회원이 질문 리스트 페이지에 있을 때, **When** 목록을 열면, **Then** 자신이
   작성한 질문만 최신순으로 보이고 각 항목에 상태 텍스트가 함께 표시된다.
5. **Given** 관리자가 답변을 등록한 질문이 있을 때, **When** 회원이 그 질문의 상세를 열면, **Then**
   상태가 "답변 완료"로 표시되고 답변 내용이 질문 아래에 표시된다.
6. **Given** 로그인한 회원에게 아직 작성한 질문이 없을 때, **When** 질문 리스트 페이지를 열면,
   **Then** 빈 목록임을 알리는 텍스트와 질문 작성으로 이동하는 수단이 표시된다.

### User Story 2 - 관리자가 답변이 필요한 질문을 찾아 답변한다 (Priority: P1)

관리자가 로그인해 전체 질문 목록을 열고, 답변 대기 상태인 질문을 식별해 상세로 들어가 답변을 작성한다.
작성한 답변에 오탈자가 있으면 같은 화면에서 수정한다.

**Why this priority**: 답변이 없으면 회원의 질문은 가치를 만들지 못한다. 스토리 1과 짝을 이루는 필수
흐름이다.

**Independent Test**: 사전 준비된 질문 데이터와 관리자 계정만 있으면, 로그인 → 전체 목록에서 답변 대기
질문 식별 → 답변 작성 → 답변 수정까지 독립적으로 수행할 수 있다.

**Acceptance Scenarios**:

1. **Given** 관리자가 로그인한 상태일 때, **When** 질문 리스트 페이지를 열면, **Then** 작성자와 무관하게
   전체 질문이 최신순으로 보이고 각 항목의 답변 상태가 텍스트로 표시된다.
2. **Given** 관리자가 답변 대기 상태의 질문 상세를 열었을 때, **When** 규칙에 맞는 답변을 입력하고
   등록하면, **Then** 답변이 저장되고 해당 질문의 상태가 "답변 완료"로 바뀐다.
3. **Given** 이미 답변이 등록된 질문일 때, **When** 관리자가 답변을 수정하고 저장하면, **Then** 수정된
   내용이 반영되고 상태는 "답변 완료"로 유지된다.
4. **Given** 답변 입력이 공백만으로 이루어졌을 때, **When** 등록을 시도하면, **Then** 저장되지 않고 답변
   필드에 오류 사유가 표시된다.
5. **Given** 관리자가 답변을 저장하는 중일 때, **When** 저장 버튼을 다시 누르면, **Then** 중복 저장이
   발생하지 않고 저장 중임을 알리는 표시가 유지된다.

### User Story 3 - 권한 경계가 지켜진다 (Priority: P1)

회원은 다른 회원의 질문에 접근할 수 없고, 답변 작성 수단을 갖지 못한다. 비회원이 보호된 화면에 접근하면
로그인 안내를 받는다. 관리자가 답변한 뒤에는 회원이 질문을 수정하거나 삭제할 수 없다.

**Why this priority**: 권한이 새면 질문 내용이 노출되거나 무단으로 변경된다. 서비스 신뢰의 전제이므로
답변 기능과 같은 우선순위이다.

**Independent Test**: 서로 다른 두 회원 계정과 질문 하나, 관리자 계정 하나가 준비되면 화면 조작과 화면을
거치지 않은 직접 요청 양쪽으로 독립 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 회원 A가 로그인한 상태이고 회원 B의 질문이 존재할 때, **When** 회원 A가 회원 B의 질문 상세
   주소로 직접 접근하면, **Then** 내용이 보이지 않고 "권한 없음" 상태가 텍스트로 표시된다.
2. **Given** 회원 A가 로그인한 상태일 때, **When** 회원 B의 질문에 대한 수정 또는 삭제 요청을 화면을
   거치지 않고 직접 보내면, **Then** 요청이 거부되고 데이터는 변경되지 않는다.
3. **Given** 로그인한 일반 회원이 질문 상세를 볼 때, **When** 화면을 확인하면, **Then** 답변 작성 수단이
   제공되지 않으며, 답변 작성 요청을 직접 보내도 거부된다.
4. **Given** 로그인하지 않은 방문자일 때, **When** 질문 리스트 페이지나 질문 상세·작성 화면에 접근하면,
   **Then** 내용 대신 로그인 안내가 표시된다.
5. **Given** 관리자가 답변을 등록한 질문일 때, **When** 작성자인 회원이 수정 또는 삭제를 시도하면,
   **Then** 요청이 거부되고 그 이유가 텍스트로 표시된다.

---

### User Story 4 - 회원이 답변 전 질문을 수정하거나 삭제한다 (Priority: P2)

질문을 등록한 뒤 내용을 잘못 적었음을 알게 된 회원이, 아직 답변이 달리지 않은 질문을 수정하거나 삭제한다.

**Why this priority**: 없어도 질문·답변 흐름은 성립하지만, 잘못 올린 질문을 되돌릴 수 없으면 사용자는
질문 작성을 주저한다.

**Independent Test**: 답변 대기 상태의 자기 질문 하나만 있으면 수정·삭제를 독립적으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 답변 대기 상태인 자기 질문의 상세 화면일 때, **When** 회원이 제목과 내용을 규칙에 맞게
   고치고 저장하면, **Then** 변경 내용이 반영되고 상태는 "답변 대기"로 유지된다.
2. **Given** 답변 대기 상태인 자기 질문일 때, **When** 회원이 삭제를 확정하면, **Then** 질문이 목록에서
   사라지고 이후 그 질문 상세에 접근할 수 없다.
3. **Given** 수정 화면에서 제목을 모두 지웠을 때, **When** 저장을 시도하면, **Then** 저장되지 않고 제목
   필드에 오류 사유가 표시되며 기존 내용은 그대로 남는다.
4. **Given** 삭제를 진행하려는 회원일 때, **When** 삭제를 요청하면, **Then** 되돌릴 수 없음을 알리는 확인
   단계를 거친 뒤에만 삭제가 수행된다.

---

### User Story 5 - 방문자가 메인 페이지에서 서비스를 이해하고 질문 작성으로 진입한다 (Priority: P2)

처음 방문한 사람이 메인 페이지에서 QANOW가 무엇을 해 주는 서비스인지, 질문이 어떤 과정을 거쳐 답변이
되는지 파악하고, 질문 작성으로 이동한다.

**Why this priority**: 이해가 없으면 가입과 질문 작성으로 이어지지 않는다. 다만 기능 자체는 스토리 1~3이
없어도 성립하지 않으므로 P2이다.

**Independent Test**: 로그인하지 않은 상태로 메인 페이지만 열어 소개·이용 흐름·질문 작성 진입 수단의
존재와 동작을 확인할 수 있다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자일 때, **When** 메인 페이지를 열면, **Then** 서비스 소개와 "질문 작성
   → 관리자 확인 → 답변 확인" 3단계 이용 흐름이 텍스트로 표시된다.
2. **Given** 로그인하지 않은 방문자일 때, **When** 질문 작성 진입 수단을 선택하면, **Then** 로그인 안내로
   이동한다.
3. **Given** 로그인한 회원일 때, **When** 질문 작성 진입 수단을 선택하면, **Then** 질문 작성 화면으로
   이동한다.
4. **Given** 메인 페이지에 시각 효과가 적용되어 있을 때, **When** 효과가 표시되지 않거나 모션 감소 설정이
   켜져 있으면, **Then** 서비스 소개·이용 흐름·질문 작성 진입 수단은 동일하게 읽히고 동작한다.

---

### Edge Cases (예외 상황)

**입력과 검증**

- 제목이나 내용이 공백 문자로만 이루어진 경우: 빈 입력으로 간주해 저장하지 않고 필드별 오류를 표시한다.
- 제목이 공백 제거 후 100자를 넘거나 내용·답변이 5000자를 넘는 경우: 저장하지 않고 초과 사실을 알린다.
- 입력에 스크립트로 해석될 수 있는 문자열이 포함된 경우: 저장·표시 과정에서 실행되지 않고 문자 그대로
  보인다.

**상태와 동시성**

- 회원이 상세 화면을 열어 둔 사이 관리자가 답변을 등록한 경우: 회원의 수정·삭제 요청은 거부되고 답변이
  달렸음을 알린다.
- 회원이 질문을 삭제한 사이 관리자가 그 질문 상세를 열어 둔 경우: 관리자의 답변 저장은 실패하고 질문이
  더 이상 없음을 알린다.
- 저장 요청이 처리되는 중 사용자가 같은 동작을 반복한 경우: 중복 생성·중복 저장이 발생하지 않는다.

**접근과 인증**

- 존재하지 않는 질문 식별자로 접근한 경우: 오류 상태를 텍스트로 알리며, 질문의 존재 여부를 추측할 수 있는
  정보를 노출하지 않는다.
- 비회원이 보호된 주소로 직접 접근한 경우: 로그인 안내를 표시한다.
- 로그인 세션이 만료된 뒤 저장을 시도한 경우: 저장되지 않고 다시 로그인해야 함을 알리며, 입력한 내용을
  잃지 않도록 안내한다.
- 잘못된 이메일 또는 비밀번호로 로그인을 시도한 경우: 어느 쪽이 틀렸는지 구분하지 않고 실패를 알린다.

**목록과 표시**

- 자신의 질문이 하나도 없는 회원, 전체 질문이 하나도 없는 관리자: 빈 목록 상태를 텍스트로 표시한다.
- 목록·상세를 불러오는 동안: 로딩 상태를 텍스트로 표시한다.
- 목록·상세를 불러오지 못한 경우: 오류 상태와 다시 시도할 수단을 표시한다.
- 제목이 매우 긴 질문이 목록에 있는 경우: 줄바꿈이나 말줄임으로 처리하며 가로 스크롤을 만들지 않는다.

**환경**

- 모바일 화면 폭에서 이용하는 경우: 핵심 시나리오를 끝까지 완료할 수 있고 주요 행동 수단이 가려지지 않는다.
- 마우스를 쓰지 않고 키보드만 사용하는 경우: 가입·로그인·로그아웃·질문 작성·수정·삭제·답변 작성·수정을
  모두 완료할 수 있다.
- 모션 감소 설정이 켜진 경우: 애니메이션 없이도 같은 정보를 얻을 수 있다.

## 화면별 목적 *(mandatory)*

### 화면 1 - 메인 페이지

- **목적**: 처음 방문한 사람이 QANOW가 무엇을 해 주는 서비스인지 이해하고 질문 작성으로 진입하게 한다.
- **표시 정보**: 서비스 소개, "질문 작성 → 관리자 확인 → 답변 확인" 3단계 이용 흐름, 현재 로그인 상태.
- **주요 행동**: 질문 작성 진입, 로그인·회원가입 진입, 로그아웃.
- **역할별 차이**: 비회원은 질문 작성 진입 시 로그인 안내로 이동하고, 회원·관리자는 각각 질문 작성 화면과
  질문 리스트 페이지로 이동한다.
- **비목표**: 질문 내용이나 목록을 노출하지 않는다.

### 화면 2 - 질문 리스트 페이지

- **목적**: 회원에게는 자신이 남긴 질문의 처리 상태를, 관리자에게는 답변이 필요한 질문을 빠르게 파악하게
  한다.
- **표시 정보**: 질문 제목, 작성 시각, 답변 상태(답변 대기·답변 완료) 텍스트. 관리자에게는 작성자 식별
  정보가 추가된다.
- **주요 행동**: 질문 상세로 이동, 질문 작성으로 이동(회원).
- **역할별 차이**: 회원은 자신의 질문만, 관리자는 전체 질문을 본다. 비회원은 로그인 안내를 본다.
- **비목표**: 검색·페이지네이션·정렬 변경을 제공하지 않는다(범위 밖).

### 화면 3 - 질문 페이지

- **목적**: 질문을 작성하고, 질문과 답변의 전체 내용을 한 화면에서 확인하며, 역할에 허용된 편집을 수행하게
  한다.
- **표시 정보**: 질문 제목·내용·작성 시각·상태, 답변이 있으면 답변 내용과 답변 시각, 입력 검증 오류.
- **주요 행동**: 질문 작성·수정·삭제(작성자, 답변 전에 한함), 답변 작성·수정(관리자).
- **역할별 차이**: 작성자 본인은 답변 전에만 수정·삭제 수단을 가지고, 관리자는 답변 작성·수정 수단을
  가진다. 작성자도 관리자도 아닌 회원과 비회원은 내용을 볼 수 없다.
- **비목표**: 파일 첨부·댓글을 제공하지 않는다(범위 밖).

## Requirements *(mandatory)*

### Functional Requirements

**계정과 인증**

- **FR-001**: System MUST 이메일과 비밀번호로 회원 계정을 생성할 수 있어야 하며, 이미 등록된 이메일로는
  계정을 생성하지 않는다.
- **FR-002**: System MUST 등록된 자격 증명으로 로그인과 로그아웃을 제공하고, 로그인 상태를 화면 이동
  중에도 유지한다.
- **FR-003**: System MUST 로그인 실패 시 이메일과 비밀번호 중 어느 쪽이 틀렸는지 구분하지 않는 실패
  메시지를 표시한다.
- **FR-004**: System MUST 관리자 역할을 회원가입 경로로 획득할 수 없게 하며, 관리자 계정은 서비스 운영자가
  사전에 지정한 계정으로만 존재한다.

**질문**

- **FR-005**: Users MUST be able to 로그인한 회원으로서 제목과 내용을 입력해 질문을 등록할 수 있다.
- **FR-006**: System MUST 등록된 질문에 "답변 대기" 또는 "답변 완료" 중 하나의 상태를 부여하고, 등록
  시점의 상태는 "답변 대기"로 한다.
- **FR-007**: System MUST 회원에게 자신이 작성한 질문만 최신순으로 나열해 보여 준다.
- **FR-008**: System MUST 관리자에게 작성자와 무관하게 전체 질문을 최신순으로 나열해 보여 주고, 각 항목의
  답변 상태를 함께 표시한다.
- **FR-041**: Users MUST be able to 질문 목록을 전체·답변 대기·답변 완료 세 가지로 좁혀 볼 수 있다.
  좁히는 수단은 목록 위에 두며, 각 구분에 해당 건수를 함께 표시한다. 관리자가 목록에 들어오면 기본으로
  "답변 대기"가 선택되어 있어야 한다. 이는 정렬 변경·검색이 아니며, FR-040의 제외 항목에 해당하지 않는다.
  (2026-08-29 추가 — 화면 설계 확정 과정에서 도출되어 사후 반영한 요구사항이다.)
- **FR-009**: System MUST 질문 상세를 작성자 본인과 관리자에게만 제공한다.
- **FR-010**: Users MUST be able to 작성자 본인으로서 상태가 "답변 대기"인 자신의 질문을 수정할 수 있다.
- **FR-011**: Users MUST be able to 작성자 본인으로서 상태가 "답변 대기"인 자신의 질문을 삭제할 수 있으며,
  삭제 전에 되돌릴 수 없음을 알리는 확인 단계를 거친다.
- **FR-012**: System MUST 상태가 "답변 완료"인 질문에 대한 작성자의 수정·삭제 요청을 거부하고 그 이유를
  표시한다.
- **FR-013**: System MUST 삭제된 질문을 목록과 상세 양쪽에서 더 이상 접근할 수 없게 한다.

**답변**

- **FR-014**: Users MUST be able to 관리자로서 질문에 답변을 작성할 수 있으며, 답변이 저장되면 해당 질문의
  상태가 "답변 완료"로 바뀐다.
- **FR-015**: Users MUST be able to 관리자로서 이미 등록된 답변을 수정할 수 있으며, 수정해도 상태는
  "답변 완료"로 유지된다.
- **FR-016**: System MUST 질문 하나당 답변을 최대 하나만 유지한다.
- **FR-017**: System MUST 관리자가 아닌 사용자의 답변 작성·수정 요청을 거부한다.

**권한과 접근 제어**

- **FR-018**: System MUST 회원이 다른 회원의 질문을 조회·수정·삭제하지 못하게 하며, 화면을 거치지 않은
  직접 요청도 동일하게 거부한다.
- **FR-019**: System MUST 권한 판정을 화면에서의 수단 노출 여부와 독립적으로, 모든 조회·저장·삭제 요청의
  처리 시점에 수행한다.
- **FR-020**: System MUST 로그인하지 않은 사용자가 보호된 화면(질문 리스트·질문 상세·질문 작성)에 접근하면
  내용 대신 로그인 안내를 표시한다.
- **FR-021**: System MUST 권한이 없는 요청에 대해 대상 자원의 존재 여부를 추측할 수 있는 정보를 노출하지
  않는다.
- **FR-022**: System MUST 로그인 세션이 유효하지 않은 상태의 저장 요청을 거부하고, 다시 로그인해야 함을
  알린다.

**입력 검증**

- **FR-023**: System MUST 질문 제목을 앞뒤 공백 제거 후 1자 이상 100자 이하로만 허용한다.
- **FR-024**: System MUST 질문 내용을 앞뒤 공백 제거 후 1자 이상 5000자 이하로만 허용한다.
- **FR-025**: System MUST 답변을 앞뒤 공백 제거 후 1자 이상 5000자 이하로만 허용한다.
- **FR-026**: System MUST 검증에 실패한 요청을 저장하지 않고, 실패한 필드와 사유를 필드 단위로 표시하며,
  사용자가 입력한 내용을 잃지 않게 한다.
- **FR-027**: System MUST 화면 조작을 거치지 않은 직접 요청에도 동일한 검증 규칙을 적용한다.
- **FR-028**: System MUST 사용자가 입력한 문자열이 화면에서 코드로 실행되지 않고 문자 그대로 표시되게
  한다.

**상태 표시**

- **FR-029**: System MUST 로딩·빈 목록·오류·권한 없음·저장 중 다섯 가지 상태를 해당 화면에서 텍스트로
  표시한다.
- **FR-030**: System MUST 질문 상태와 시스템 상태를 색상만으로 구분하지 않고 항상 텍스트 레이블을 함께
  제공한다.
- **FR-031**: System MUST 저장이 진행되는 동안 같은 요청이 중복 실행되지 않게 하고, 진행 중임을 표시한다.
- **FR-032**: System MUST 오류 상태에서 사용자가 다시 시도할 수 있는 수단을 제공하며, 내부 예외 정보를
  노출하지 않는다.

**메인 페이지**

- **FR-033**: System MUST 메인 페이지에 서비스 소개와 "질문 작성 → 관리자 확인 → 답변 확인" 3단계 이용
  흐름을 텍스트로 표시한다.
- **FR-034**: System MUST 메인 페이지에 질문 작성으로 진입하는 수단을 제공하고, 비회원이 선택하면 로그인
  안내로 이동시킨다.
- **FR-035**: System MUST 메인 페이지의 시각 효과가 표시되지 않거나 모션이 제거된 상태에서도 소개·이용
  흐름·질문 작성 진입 수단이 동일하게 읽히고 동작하게 한다.

**공통 사용성**

- **FR-036**: Users MUST be able to 마우스 없이 키보드만으로 회원가입·로그인·로그아웃·질문 작성·수정·
  삭제·답변 작성·수정을 완료할 수 있다.
- **FR-037**: System MUST 데스크톱 화면 폭과 모바일 화면 폭 모두에서 핵심 시나리오를 완료할 수 있게 하고,
  모바일 폭에서 가로 스크롤을 만들거나 주요 행동 수단을 가리지 않는다.
- **FR-038**: System MUST 모션 감소를 선호하는 환경에서 애니메이션을 제거하거나 정적 표현으로 대체하고,
  애니메이션에만 의존해 정보를 전달하지 않는다.
- **FR-039**: System MUST 세 화면에서 같은 의미의 요소(상태 레이블·주요 행동·오류 표시)에 같은 용어와 같은
  표현을 사용한다.

**범위**

- **FR-040**: System MUST NOT 파일 첨부, 댓글, 검색, 페이지네이션, 소셜 로그인, 통계 대시보드를 제공하지
  않으며, 이를 위한 화면·데이터·설정도 두지 않는다.

### Key Entities

- **사용자(User)**: 서비스를 이용하는 주체이다. 식별용 이메일, 인증 수단, 역할(회원·관리자)을 가진다.
  비회원은 사용자 기록이 없는 상태를 뜻한다.
- **질문(Question)**: 회원이 남긴 문의이다. 제목, 내용, 작성자, 작성 시각, 최종 수정 시각, 답변 상태를
  가진다. 작성자 한 명에 속하며 답변을 최대 하나 가진다.
- **답변(Answer)**: 관리자가 질문에 대해 남긴 회신이다. 내용, 작성한 관리자, 작성 시각, 최종 수정 시각을
  가진다. 질문 하나에 속한다.
- **세션(Session)**: 로그인한 사용자와 그 역할을 요청 시점에 식별하기 위한 상태이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 방문한 사람이 가입부터 첫 질문 등록까지 3분 이내에 완료한다.
- **SC-002**: 메인 페이지를 처음 본 사람의 90% 이상이 "질문 작성 → 관리자 확인 → 답변 확인" 3단계를
  안내 없이 설명할 수 있다.
- **SC-003**: 관리자가 답변이 필요한 질문을 목록에서 찾는 데 30초 이내가 걸린다.
- **SC-004**: 회원이 자신의 질문 상태(답변 대기·답변 완료)를 목록 화면에서 5초 이내에 식별한다.
- **SC-005**: 타인의 질문에 접근·수정·삭제하려는 시도가 화면 경로와 직접 요청 경로 모두에서 100% 거부된다.
- **SC-006**: 입력 규칙 경계값(0자·1자·최대치·최대치 초과·공백만) 시험에서 100%가 규칙대로 처리된다.
- **SC-007**: 핵심 시나리오(회원 질문 등록·관리자 답변)가 데스크톱과 모바일 화면 폭 모두에서 100%
  완료된다.
- **SC-008**: 주요 행동 8종(가입·로그인·로그아웃·질문 작성·수정·삭제·답변 작성·수정)이 키보드만으로 100%
  완료된다.
- **SC-009**: 다섯 가지 상태(로딩·빈 목록·오류·권한 없음·저장 중)가 색상을 제거한 화면에서도 100% 구분된다.
- **SC-010**: 질문 등록·수정·삭제와 답변 등록·수정을 마친 뒤 결과가 화면에 반영되었음을 사용자가 즉시
  확인할 수 있다(별도 새로고침 불필요).
- **SC-011**: 질문 상세 화면에서 질문 내용과 답변 내용을 스크롤 외의 추가 조작 없이 함께 확인할 수 있다.

### 측정 방법

- **SC-005~SC-011**은 자동 테스트로 판정한다(단위·계약·엔드투엔드·접근성 검사).
- **SC-001·SC-002·SC-003·SC-004**는 사람을 대상으로 하는 지표이므로 자동 판정 대상에서 제외하고,
  **수업 시연에서 3~5명을 관찰한 기록으로 판정한다.** 관찰 항목은 (1) 가입~첫 질문 등록 소요 시간,
  (2) 메인을 본 뒤 3단계 흐름을 설명할 수 있는지, (3) 관리자가 답변 대기 질문을 찾는 데 걸린 시간,
  (4) 목록에서 상태를 식별하는 데 걸린 시간이다. 관찰 기록이 없으면 "미측정"으로 남기며,
  이 네 항목의 미측정은 구현 완료를 막지 않는다.
  (2026-08-29 결정 — 측정 절차가 없어 완료 판정이 불가능하던 문제를 닫는다.)

## Assumptions

- 인증은 이메일과 비밀번호를 사용하는 표준 방식이며, 이메일 소유 확인 절차와 비밀번호 재설정은 이번 범위에
  포함하지 않는다(소셜 로그인은 명시적으로 범위 밖이다).
- 관리자 계정은 서비스 운영자가 사전에 준비하며, 화면을 통한 관리자 지정·해제 기능은 제공하지 않는다.
- 질문은 작성자 본인과 관리자에게만 공개된다. 비회원이나 다른 회원이 볼 수 있는 공개 질문 목록은 없다.
- 질문당 답변은 하나이다. 사용자 입력에 "기존 답변 수정"만 있고 답변 추가·삭제가 없으므로 단일 답변으로
  본다.
- 질문 삭제는 목록과 상세 양쪽에서 접근할 수 없게 되는 것을 뜻하며, 사용자에게 복구 수단을 제공하지 않는다.
- 목록 정렬은 최신순 고정이다. 정렬 변경·검색·페이지네이션은 범위 밖이므로, 초기 데이터 규모는 한 화면에서
  훑을 수 있는 수준으로 가정한다.
- 화면 표기 언어는 한국어 하나이며 다국어 지원은 범위 밖이다.
- 상태 명칭은 질문 상태 두 가지("답변 대기", "답변 완료")와 시스템 상태 다섯 가지(로딩·빈 목록·오류·
  권한 없음·저장 중)로 고정하며, 세 화면에서 같은 용어를 사용한다.
