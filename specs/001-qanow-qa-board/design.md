## 0. 이 문서의 지위

- 본 문서는 **확정 프로토타입에 실제로 들어 있는 값과 규칙만** 옮긴 것이다. 프로토타입에 없는 요소를
  추론해 채우지 않았다. 미정 사항은 8절 말미와 25절에 "미결"로 남겼다.
- `design-brief.md`가 지시서(무엇을 만들지)라면 본 문서는 **확정서**(무엇이 만들어졌는지)이다. 두 문서가
  어긋나는 지점은 본 문서가 우선하며, 어긋난 이유를 각 절에 밝혔다.
- 구현은 본 문서의 값을 그대로 쓴다. 값을 바꾸려면 문서를 먼저 고친다(헌장 원칙 XII).
- 프로토타입은 시각·구조 확정용이며 **기술 스택을 지정하지 않는다**. CSS 선언은 값의 출처로만 인용한다.

## 1. 디자인 콘셉트와 목표

**콘셉트**: *Aurora Console* — 어두운 네이비 Hero가 첫인상을 만들고, 스크롤 아래부터 밝은 Surface로
전환되어 내부 작업 화면까지 이어진다. 다크는 "서비스를 소개하는 자리", 라이트는 "질문을 읽고 쓰는 자리"로
역할을 나눈다. 헤더만은 세 화면 모두 다크로 고정해 두 표면을 하나의 서비스로 묶는다.

시안 A(Aurora Console)와 시안 B(Editorial Line)를 8개 기준으로 비교한 결과 A 3승·B 4승·1무였으나,
사용자가 A 방향을 지정했다. A의 두 약점은 다음과 같이 보완해 확정했다.

| A의 약점 | 확정된 보완 |
|---|---|
| 메인(다크)과 내부(라이트)의 표면이 갈림 | **헤더를 전 화면 다크로 고정**하고, 메인 Hero 아래 88px 전환 밴드로 이어붙였다 |
| 다크+오로라+그리드가 흔한 AI 랜딩 문법과 겹침 | 3D 구체·파티클·텍스트 그라데이션·자동 재생을 전부 배제하고, 움직이는 요소를 2종으로 제한했다 |

**목표와 근거**

| # | 목표 | 근거 |
|---|---|---|
| 1 | 첫 화면에서 질의응답 서비스임을 전달한다 | SC-002, FR-033 |
| 2 | 질문 작성 진입 문턱을 낮춘다 | SC-001, FR-034 |
| 3 | 관리자가 답변 대기 질문을 빠르게 찾는다 | SC-003, FR-008 |
| 4 | 상태를 오해 없이 전달한다 | SC-004, FR-029·FR-030 |
| 5 | 시각 효과가 콘텐츠를 가리지 않는다 | FR-035, 헌장 원칙 VI |
| 6 | 세 화면이 하나의 서비스로 읽힌다 | FR-039, 헌장 원칙 V |

**서비스 이름**: QANOW — 워드마크는 항상 **대문자 + 모노스페이스 + 자간 0.16em**으로 쓴다.

## 3. 세 핵심 화면의 정보 구조

### 3.1 메인 페이지 (FR-033·FR-034·FR-035)

```
Header(다크, 고정 규칙)
Hero(다크)          ├ eyebrow → 제목 → 보조 문구 → CTA 2개 → 안내 문구
                    └ 우측: 질문 카드 → 연결선(관리자 확인) → 답변 카드
전환 밴드(88px)
이용 흐름(라이트)   ├ kicker "이용 흐름"
                    ├ 제목 "질문 작성 → 관리자 확인 → 답변 확인"
                    └ 3단계(01/02/03) 가로 3열
마무리 CTA(흰 면)   └ 문장 + Primary CTA
Footer(다크)
```
정보 우선순위: ① 제목 ② Primary CTA ③ 보조 문구 ④ 3단계 흐름 ⑤ Secondary CTA ⑥ 헤더 ⑦ **배경 효과(최하위)**.
**비목표**: 질문 목록·질문 내용을 노출하지 않는다.

### 3.2 질문 리스트 페이지 (FR-007·FR-008·FR-029)

```
Header
Page Header   ├ 제목(역할별) + 설명
              └ 우측: 새 질문 작성(회원만)
상태 탭       └ 전체 / 답변 대기 / 답변 완료 (각 건수)
본문          └ [기본] 목록 · [로딩] 스켈레톤 · [빈 목록] 안내 · [오류] 재시도
```
정보 우선순위: ① 상태 배지 ② 제목 ③ 작성일 ④ 작성자(관리자만) ⑤ 목록 성격 ⑥ 작성 진입.
**비목표**: 검색·정렬 변경·페이지네이션을 두지 않는다(FR-040).

### 3.3 질문 페이지 (FR-005·FR-009·FR-010~FR-017·FR-023~FR-026)

한 화면이 네 가지 상태를 갖는다. **화면을 추가하지 않는다**(헌장 원칙 XI).

| 상태 | 진입 경로 | 구성 |
|---|---|---|
| 작성 | 메인 CTA, 리스트 "새 질문 작성", 빈 목록 안내 | 제목 입력 · 내용 입력 · 취소/등록하기 |
| 상세 | 목록 항목 선택 | 배지 · 제목 · 메타 · 질문 블록 · 답변 블록 · 역할별 행동 |
| 수정 | 상세의 "수정하기"(답변 전·작성자만) | 값이 채워진 작성 폼 · 취소/저장하기 |
| 답변 | 상세의 "답변 작성하기 / 답변 수정하기"(관리자만) | 상세 + 답변 입력 영역 |

정보 우선순위: ① 제목 ② 상태 배지 ③ 질문 본문 ④ 답변 본문 ⑤ 행동 버튼 ⑥ 작성 시각 ⑦ 목록 복귀.

## 4. 화면별 레이아웃

| 화면 | 컨테이너 최대 폭 | 좌우 여백(D/M) | 열 구성 |
|---|---|---|---|
| 메인 Hero | 1200px | 40 / 20 | `588px + 1fr`, gap 56 → 모바일 1열 |
| 메인 흐름·마무리 | 1120px | 40 / 20 | 3열 → 모바일 1열 |
| 질문 리스트 | 960px | 40 / 20 | 단일 열 |
| 질문 페이지 | 960px, **본문 720px** | 40 / 20 | 단일 열 |

- 페이지 세로 여백: 데스크톱 `40px 40px 72px`, 모바일 `24px 20px 48px`.
- 메인 섹션 세로 여백: 데스크톱 `40px 40px 76px`, 모바일 `20px 20px 36px`.
- Hero 세로 여백: 데스크톱 `84px 40px 96px`, 모바일 `34px 20px 40px`.
- 질문·답변 본문은 **720px 폭 제한**으로 한 줄 길이를 통제한다(SC-011, design-brief 12절).
- 리스트와 질문 페이지는 **좌우 2단으로 나누지 않는다**. 모바일과 구조가 어긋나는 것을 막기 위함이다.

## 5. 화면 간 이동

확정된 이동 경로이며, 프로토타입에서 실제로 동작한다.

```
              ┌────────────── 메인 페이지 ──────────────┐
              │ 질문 작성하기 → 질문 페이지(작성)        │
              │ 내 질문 확인하기 → 질문 리스트           │
              │ 마무리 CTA → 질문 페이지(작성)           │
              └──────────────────┬──────────────────────┘
   헤더 QANOW / "서비스 소개" ────┘        헤더 "내 질문"·"문의 관리"
                                                  ↓
                                        ┌── 질문 리스트 ──┐
                          새 질문 작성 ←┤ (회원만)         │
                                        │ 목록 항목 선택  │→ 질문 페이지(상세)
                                        └─────────────────┘        │
                                                 ↑                 │
                          "← 목록으로 돌아가기" ──┴─────────────────┘
```

- **되돌아가기 문구는 역할과 무관하게 `← 목록으로 돌아가기` 하나로 고정**한다. 역할별 제목을 넣으면
  "내 질문(으)로"처럼 조사가 깨지고 용어가 갈린다(FR-039).
- 되돌아가기는 **상세·답변 상태에서만** 노출한다. 작성·수정 폼에서는 하단 "취소"만 두어 이탈 경로를
  하나로 유지한다(FR-026, 입력 보존).
- 삭제 확정 후에는 리스트로 이동하며 목록이 비게 된다(FR-013).
- 비회원이 리스트에 접근하면 목록 대신 **로그인 안내**를 표시한다(FR-020).
- 브라우저 뒤로가기에 의존하지 않는다. 모든 내부 화면에서 한 번의 조작으로 목록에 닿는다.

## 6. 회원과 관리자 상태 차이

역할 차이는 **요소의 존재/부재**로 표현한다. 권한 없는 요소를 흐리게(disabled) 띄우지 않는다.

| 지점 | 비회원 | 회원 | 관리자 | 근거 |
|---|---|---|---|---|
| 헤더 역할 배지 | `비회원` | `회원` | `관리자` | — |
| 헤더 두 번째 링크 | `내 질문` | `내 질문` | `문의 관리` | FR-007·FR-008 |
| 메인 안내 문구 | 로그인 안내형 | 비공개 안내형 | 비공개 안내형 | FR-020 |
| 리스트 제목 | — (로그인 안내) | `내 질문` | `문의 관리` | FR-007·FR-008 |
| 리스트 설명 | — | `내가 남긴 질문과 답변 상태를 확인할 수 있습니다.` | `답변이 필요한 질문을 먼저 확인해 주세요.` | — |
| 목록 범위 | 접근 불가 | 본인 질문만 | 전체 질문 | FR-007·FR-008·FR-018 |
| 목록 열 | — | 제목·작성일·상태 | **+ 작성자** | FR-008 |
| 기본 상태 필터 | — | `전체` | **`답변 대기`** | SC-003 |
| 새 질문 작성 버튼 | 없음 | 있음 | **없음** | FR-005 |
| 질문 수정·삭제 | 없음 | 답변 전에만 | 없음 | FR-010~FR-012 |
| 답변 입력 영역 | 없음 | **없음** | 있음 | FR-017 |
| 상세 메타 | — | `작성 <일시>` | `작성자 <이메일> · 작성 <일시>` | FR-008 |

**작성자 식별값은 이메일이다.** 명세가 보유한 사용자 식별 정보가 이메일뿐이므로(FR-001, Key Entities)
닉네임·아바타를 만들지 않았다.

## 7. Header와 Navigation 규칙

세 화면이 **같은 헤더 하나**를 쓴다(FR-039, 헌장 원칙 V).

| 항목 | 데스크톱 | 모바일 |
|---|---|---|
| 배경 | `--ink900` (#080D1C) | 동일 |
| 높이 | 68px | 56px |
| 좌우 여백 | 40px | 20px |
| 하단 경계 | `1px solid rgba(255,255,255,.12)` | 동일 |
| 워드마크 | 모노 600 17px, 자간 .16em, `--onDark` | 15px |
| 링크 간격 | 24px | 14px |
| 링크 | 400 14px, `--onDark2` | 13px |
| 현재 화면 링크 | 700, `--onDark` | 동일 |
| 역할 배지 | 높이 26px, 좌우 10px, 테두리 `rgba(255,255,255,.34)`, 600 11.5px | 동일 |

- **내비게이션 항목은 3개뿐이다**: 워드마크(→ 메인), `서비스 소개`(→ 메인), `내 질문`/`문의 관리`(→ 리스트).
  항목이 적으므로 **접이식(햄버거) 메뉴를 만들지 않는다.** 모바일에서도 그대로 노출한다.
  열기/닫기 상태와 포커스 가두기 로직이 사라져 구현이 단순해지고(원칙 XI) 키보드 접근이 쉬워진다(FR-036).
- 워드마크와 링크는 모두 **버튼**이며 키보드로 도달·실행할 수 있다.
- 헤더는 다크 표면이므로 **포커스 링에 `--focusDark`를 쓴다**(21절 참조).

## 8. Page Header 규칙

리스트·질문 페이지의 제목 영역 규칙이다. 메인 페이지에는 Page Header가 없다(Hero가 대신한다).

- 배치: 좌측 `제목 + 설명`, 우측 `주요 행동 버튼`. `align-items: flex-end`, 간격 20px.
- 하단에 `1px solid --divider` 구분선, 아래 여백 20px.
- 제목 `700 30px/1.35`(모바일 24px), 설명 `400 14.5px/1.7 --fg2`, 제목-설명 간격 8px.
- **모바일에서는 세로로 쌓고 버튼을 전폭**으로 만든다(간격 14px).
- 질문 작성·수정 폼에서는 우측 버튼 없이 제목·설명만 둔다.
- 되돌아가기 버튼은 Page Header **위**에 놓는다(600 13.5px, `--fg2`, 아래 여백 14px).

```
│  z0  Aurora  (3중 radial-gradient, blur 6px)                     │
│  z1  Grid    (44px 격자, opacity .06, 방사형 마스크)              │
│  z2  Scrim   (좌→우 어둡게, 텍스트 대비 확보용)                    │
│  z3  Content ┌ 588px ────────────┬ 1fr ──────────────────┐        │
│              │ eyebrow           │  ┌ 질문 카드 (fl1)    │        │
│              │ 제목 56px 2줄     │  │ Q · 회원 / 답변 대기│        │
│              │ 보조 문구 18px    │  ├ 연결선 64px + 점    │        │
│              │ CTA 2개           │  │ "관리자 확인"       │        │
│              │ 안내 문구 13px    │  └ 답변 카드 (fl2, ml40)│       │
│              └───────────────────┴───────────────────────┘        │
└──────────────────────────────────────────────────────────────────┘
    ↓ 전환 밴드 88px (linear-gradient ink900 → canvas)
```

- 콘텐츠 격자 `588px 1fr`, gap 56px, 최대 1200px, 세로 중앙 정렬.
- **모바일은 1열**이며 순서는 `eyebrow → 제목 → 보조 문구 → CTA(전폭 2개) → 질문/답변 카드 → 흐름`이다.
- 제목: 데스크톱 `700 56px/1.24`, 자간 -.02em / 모바일 `700 32px/1.34`. 줄바꿈 위치를 고정한다.
- CTA: Primary `질문 작성하기`(파란 채움), Secondary `내 질문 확인하기`(흰 테두리 42% 불투명).
- 질문·답변 카드는 **실제 질문 목록이 아니라 흐름 설명용 예시**이다. 목록 형태로 늘리지 않는다.
- 카드 규격: 배경 `--ink700`, 테두리 `rgba(255,255,255,.16)`, 반경 12px, 여백 18/20px.
  역할 레이블 `700 11.5px 자간 .12em --onDark3`, 제목 `700 16px/1.55`, 본문 `400 14px/1.8`,
  시각 `모노 12px --onDark3`.
- 연결선: 높이 64px, 좌측 2px 세로선(바이올렛 그라데이션), 중앙에 8px 점(글로우 4px),
  레이블 `관리자 확인`은 점에서 30px 떨어뜨린다.

## 10. Aurora Gradient · Grid Glow · Floating Card 효과

**세 겹이 전부이며, 네 번째 장식 레이어를 추가하지 않는다**(FR-035, 헌장 원칙 VI).

### 10.1 Aurora Gradient (z-index 0)
`inset: -20% -10%`, `filter: blur(6px)`, 세 광원의 합:

| 광원 | 위치·크기 | 색 |
|---|---|---|
| 1 | `38% 44% at 20% 26%` | `rgba(42,79,224,.28)` → transparent 70% |
| 2 | `42% 46% at 74% 16%` | `rgba(107,70,229,.50)` → transparent 70% |
| 3 | `46% 40% at 86% 70%` | `rgba(58,169,224,.20)` → transparent 72% |

가장 밝은 광원(2)은 **오른쪽 위**, 즉 텍스트가 아니라 카드 뒤에 놓인다. 이미지·동영상·Lottie를 쓰지 않고
CSS 그라데이션만 쓴다(성능 예산).

### 10.2 Grid Glow (z-index 1)
1px 흰 선, 격자 44px, `opacity .06`,
마스크 `radial-gradient(70% 60% at 50% 40%, #000 30%, transparent 100%)`로 가장자리를 지운다.

### 10.3 Scrim (z-index 2) — 대비 확보 장치
데스크톱 `linear-gradient(90deg, rgba(8,13,28,.92) 0%, .72 34%, .10 62%, 0 100%)`,
모바일 `linear-gradient(180deg, rgba(8,13,28,.88), rgba(8,13,28,.55))`.
**텍스트가 놓이는 좌측(모바일은 상단)을 다시 어둡게 덮어 헤드라인 대비를 확보한다.** 이 레이어를 빼면
17.74:1이 보장되지 않으므로 제거하지 않는다.

### 10.4 Floating Card
질문 카드와 답변 카드가 각각 `translateY(0 → -7px)`로 부유한다. 답변 카드는 좌측 여백 40px로 어긋나
배치되어 흐름의 방향을 만든다.

### 10.5 애니메이션 총량 (확정)

| 이름 | 대상 | 주기 | 변화 |
|---|---|---|---|
| `drift` | Aurora | 22s alternate | `translate3d(0,0,0)` → `(-1.4%, 1.6%, 0)` |
| `floaty` | 질문 카드 | 11s alternate | `translateY(0 → -7px)` |
| `floaty` | 답변 카드 | 13s alternate-reverse | `translateY(0 → -7px)` |
| `sp` | 로딩 스피너 | 1s linear | 회전 |
| `pulse` | 스켈레톤 바 | 1.6s | `opacity 1 → .55` |

전부 `transform`·`opacity`만 쓴다. **스크롤 패럴랙스·마우스 추적·자동 재생 캐러셀·타이핑 효과는 없다.**

### 11.3 모바일 — 카드(card)

## 12. 질문 작성 폼 구조

작성과 수정이 **같은 폼**을 쓴다. 다른 것은 제목·설명·버튼 라벨·초기값뿐이다.

| 요소 | 작성 | 수정 |
|---|---|---|
| 제목 | `질문 작성` | `질문 수정` |
| 설명 | `제목과 내용을 남기면 관리자가 확인합니다.` | `답변이 등록되기 전에만 수정할 수 있습니다.` |
| 제출 버튼 | `등록하기` | `저장하기` |
| 초기값 | 비어 있음 | 기존 제목·내용 |

- **필드 라벨은 항상 필드 위에 보인다**(`700 13.5px`, 아래 여백 8px). 플레이스홀더를 라벨 대신 쓰지 않는다.
- 제목: 단일행 입력, 높이 48px, 좌우 14px, 테두리 `1px --inputBorder`, 반경 8px, **글자 16px**.
  플레이스홀더 `질문 제목을 입력하세요`.
- 내용: 여러 줄 입력, 최소 높이 **240px**(모바일 180px), 여백 14px, `400 16px/1.8`, 세로 리사이즈 허용.
  플레이스홀더 `문의하실 내용을 자세히 적어 주세요`.
- 필드 아래 한 줄에 **도움말(좌) + 글자 수(우)** 를 둔다(`400 12.5px --fg2`, 글자 수는 모노).
  - 제목 `100자 이내로 입력해 주세요.` / `0 / 100` (FR-023)
  - 내용 `5000자 이내로 입력해 주세요.` / `0 / 5000` (FR-024)
- **오류 시**: 테두리를 `--err`로 바꾸고 같은 자리의 도움말을 오류 문구로 교체한다(`--err`, 700).
  `제목을 입력해 주세요.` / `내용을 입력해 주세요.` 입력값은 유지한다(FR-026).
- 행동 줄: 상단 `1px --divider`, 위 여백 32px/24px, 버튼 간격 10px, `취소`(Secondary) → `등록하기`(Primary).
  **모바일은 `column-reverse` 전폭**이라 Primary가 위에 온다.
- **저장 중**: Primary 버튼 비활성 + 라벨이 `저장 중입니다...`로 바뀌고, 옆에 `저장 중` 배지를 표시한다.
  중복 제출을 막는다(FR-031).

## 13. 질문 상세와 답변 영역 구조

```
← 목록으로 돌아가기
┌ .qhead ────────────────────────────────┐
│ [답변 대기|답변 완료] 배지               │
│ 제목 28px                               │
│ 작성 메타(관리자는 작성자 포함)          │
└─────────────────────────────────────────┘
│ 질문        ← 좌측 4px --divider 획
│ 본문 16px/1.9
│ 관리자 답변 ← 좌측 4px --pri 획
│ [답변 있음] 본문 + 답변 일시
│ [답변 없음] 점선 안내 박스
(역할별 행동 영역)
```

- **질문 블록과 답변 블록은 좌측 4px 획으로 구분한다.** 질문은 `--divider`(중립), 답변은 `--pri`(파랑).
  획만으로 구분하지 않고 각 블록에 `질문` / `관리자 답변` 레이블을 단다(`700 12.5px 자간 .1em --fg2`).
- 본문 `400 16px/1.9`, `white-space: pre-wrap`, `overflow-wrap: anywhere`. 폭 720px 제한.
  줄 간격 1.9는 긴 한국어 본문 가독성을 위한 값이다(SC-011).
- **답변 없음**: 점선 테두리 박스에 `아직 답변이 등록되지 않았습니다. 관리자가 확인 후 등록합니다.`(FR-006).
- **답변 있음**: 본문 아래에 `답변 <일시>`를 `400 13px/1.6 --fg2`로 붙인다.

### 13.1 역할·답변 상태별 행동 영역 (FR-010~FR-017)

| 역할 | 답변 | 표시되는 것 |
|---|---|---|
| 회원 | 전 | `수정하기`(Secondary) + `삭제하기`(오류색 테두리) |
| 회원 | 전, 삭제 확인 중 | 위 버튼 감춤 → **삭제 확인 블록** |
| 회원 | 후 | 버튼 없음 + 안내 `답변이 등록된 질문은 수정하거나 삭제할 수 없습니다.` |
| 관리자 | 전 | `답변 작성하기`(Primary) |
| 관리자 | 후 | `답변 수정하기`(Primary) |
| 관리자 | 답변 입력 중 | 답변 입력 영역 + `취소` / `답변 등록`·`답변 저장` |

- **삭제 확인은 인라인 블록이다**(FR-011). 모달을 쓰지 않아 화면이 늘지 않고 포커스 가두기 로직이
  필요 없다. 배경 `#FDF8F7`, 테두리 `1px #E4B8B2`, 반경 12px, 여백 20px.
  문구: `이 질문을 삭제하시겠습니까?`(굵게, 줄바꿈) `삭제한 질문은 되돌릴 수 없습니다.`
  버튼: `취소`(Secondary) / `삭제하기`(오류색 테두리). 모바일은 세로 전폭.
- **삭제는 붉은 채움 버튼을 쓰지 않는다.** 오조작을 줄이기 위해 테두리형으로 둔다.
- 답변 입력 영역은 작성 폼과 같은 입력·카운터·행동 줄 규칙을 따른다(`0 / 5000`, FR-025).
- 회원 화면에는 **답변 입력 요소가 아예 존재하지 않는다.** 비활성 상태로 띄우지 않는다(FR-017).

## 14. Loading · Empty · Error · Unauthorized 상태

다섯 가지 상태를 모두 **텍스트로** 표시한다(FR-029). 색·아이콘만으로 구분하지 않는다(FR-030).

| 상태 | 화면 | 표현 | 문구 | 다음 행동 |
|---|---|---|---|---|
| **로딩** | 리스트 | 스켈레톤 4행(**행 높이 58px로 실제 행과 동일**) + 하단 스피너 | `불러오는 중입니다.` | — |
| **로딩** | 질문 | 스켈레톤 블록(제목 22px + 본문 3줄) + 스피너 | `불러오는 중입니다.` | — |
| **빈 목록(회원)** | 리스트 | 상태 박스 + `빈 목록` 배지 | `아직 남긴 질문이 없습니다.` / `첫 질문을 남겨보세요.` | `질문 작성하기` |
| **빈 목록(관리자)** | 리스트 | 같은 박스, **버튼 없음** | `등록된 질문이 없습니다.` / `새 문의가 들어오면 이 목록에 표시됩니다.` | — |
| **오류** | 리스트 | 오류색 박스(테두리 `#F0BDB6`, 배경 `#FDF8F7`) + `오류` 배지 | `목록을 불러오지 못했습니다.` / `잠시 후 다시 시도해 주세요.` | `다시 시도` |
| **오류** | 질문 | 동일 | `내용을 불러오지 못했습니다.` / `잠시 후 다시 시도해 주세요.` | `다시 시도` |
| **권한 없음** | 질문 | 중립 박스 + `권한 없음` 배지 | `이 질문에 접근할 권한이 없습니다.` / `내가 작성한 질문만 열어볼 수 있습니다.` | `목록으로 이동` |
| **로그인 필요** | 리스트 | 중립 박스 + `로그인 필요` 배지 | `로그인이 필요한 화면입니다.` / `로그인하면 내가 남긴 질문과 답변을 확인할 수 있습니다.` | `로그인` / `회원가입` |
| **저장 중** | 질문 | 버튼 비활성 + 라벨 교체 + `저장 중` 배지 | `저장 중입니다...` | 중복 제출 차단 |

- 상태 박스 공통 규격: 흰 배경, 테두리 `--divider`, 반경 12px, 여백 `44px 24px`, 가운데 정렬, 위 여백 16px.
  제목 `700 17px/1.5`, 설명 `400 14px/1.75 --fg2`.
- **권한 없음 문구는 질문의 존재 여부를 알려주지 않는다**(FR-021).
- **오류 문구에 내부 예외를 노출하지 않는다**(FR-032).
- 로딩은 해당 영역 안에서만 일어난다. 화면 전체를 덮는 오버레이를 쓰지 않는다.
- 저장 중은 **질문 페이지 전용**이다. 리스트에는 저장 중 표시가 없다.

## 19. 버튼 · 입력창 · 카드 · 배지 규칙

### 19.1 모서리 반경
버튼·입력 **8px**, 카드·패널·목록·상태 박스 **12px**, 배지 **6px**, 모바일 프레임 26px.
**16px를 넘지 않으며 알약(pill) 형태를 쓰지 않는다.**

### 19.2 버튼 — 다섯 가지뿐

| 종류 | 스타일 | 쓰는 곳 |
|---|---|---|
| Primary | 배경 `--pri`, 흰 글자, hover `--pri2` | 화면당 하나 |
| Secondary | 테두리 `--inputBorder`, 글자 `--fg`, hover 테두리 `--fg` | 취소·보조 행동 |
| Destructive | 테두리 `#C98B84`, 글자 `--err` | 삭제하기 |
| Dark Primary | 배경 `--pri`, 흰 글자 | Hero 위 |
| Dark Secondary | 테두리 `rgba(255,255,255,.42)`, 글자 `--onDark` | Hero 위 |

- 높이 **데스크톱 44px / 모바일 48px**, 좌우 20px, `700 15px/1`. 작은 버튼 38px·좌우 14px·14px.
- **터치 대상은 항상 44×44px 이상**이다.
- `disabled` → `opacity .6`, 커서 기본. 저장 중에는 라벨도 함께 바뀐다.
- 포커스 → `outline 2px` + `offset 2px`. hover가 포커스 표시를 대신하지 않는다.

### 19.3 입력창
- 단일행 48px / 여러 줄 최소 240px(모바일 180px), 테두리 `1px --inputBorder`, 흰 배경, 글자 16px.
- 포커스 시 테두리를 `--pri`로 바꾸고 `outline 2px --pri`(offset 2px)를 더한다.
- 오류 시 테두리 `--err` + 필드 아래 오류 문구. **아이콘·색만으로 알리지 않는다.**
- 라벨은 항상 위에 보이고, 도움말과 글자 수는 필드 아래 한 줄에 좌·우로 나눈다.

### 19.4 카드
- 밝은 표면: 흰 배경 + `1px --divider` 테두리 + 반경 12px. **그림자를 쓰지 않는다.**
  (프레임 바깥의 프로토타입 섀도만 예외이며 제품 화면이 아니다.)
- 어두운 표면: 배경 `--ink700` + `1px rgba(255,255,255,.16)`. **배경 흐림(backdrop blur)을 쓰지 않는다.**
- 목록 행은 카드 안에서 `1px --divider`로만 나눈다. 행마다 그림자를 넣지 않는다.

### 19.5 배지
- 구성 `점(6px, currentColor) + 텍스트`. **텍스트가 반드시 있다.**
- 높이 24px, 좌우 8px, 반경 6px, `700 12px/1`, 1px 테두리, 줄바꿈 금지.
- 종류는 7가지: 답변 대기·답변 완료(밝은/어두운 각 1벌), 오류, 권한 없음/빈 목록/로그인 필요, 저장 중.
- 배치: 데스크톱 목록은 행 우측 끝, 모바일 카드는 **제목 위**, 상세는 제목 위.

## 21. 키보드 포커스와 접근성

기준은 **WCAG 2.2 AA**이다. 시안과 접근성 기준이 충돌하면 접근성이 이긴다(헌장 개발 워크플로).

- **모든 조작 요소가 버튼 또는 입력이다.** 헤더 워드마크·내비게이션 링크, 목록 행 전체, 탭, 상태 박스의
  행동까지 키보드로 도달·실행할 수 있다(FR-036, SC-008).
- **포커스 표시**: `outline 2px` + `offset 2px`. 목록 행만 `offset -2px`(행 경계 안쪽).
  포커스를 숨기는 스타일이 없다.
- **표면별 포커스 색**: 밝은 표면 `--pri`(6.38:1), **어두운 표면 `--focusDark`(7.12:1)**.
- 포커스 순서는 시각적 순서와 같다. 사용자 정의 위젯(모달·드롭다운)이 없어 포커스 가두기가 필요 없다.
- 상태는 항상 텍스트를 동반한다. **회색조로 변환해도 구분이 유지된다**(FR-030).
- 라벨과 입력을 연결하고, 오류는 필드 단위로 표시한다(FR-026). 오류 발생 시 첫 오류 필드로 포커스를 옮긴다.
- 저장 중·오류 같은 화면 변화는 보조 기술에 알려져야 한다(FR-031·FR-032).
- 터치 대상 44×44px 이상, 인접 대상 간 8px 이상.
- 200% 확대에서 내용 손실과 가로 스크롤이 없어야 한다.

> ⚠️ **구현 시 반드시 분리할 것**: 확정 프로토타입의 `.btn:focus-visible`은 밝은·어두운 표면 모두
> `--pri`를 쓴다. `--pri`는 `--ink900` 위에서 **3.04:1**로 최소선에 아슬하게 걸친다. 헤더·Hero의
> 버튼과 링크에는 **`--focusDark`를 적용**해야 한다. 25절 미결 항목 2번.

## 22. prefers-reduced-motion 규칙

**모든 애니메이션이 `@media (prefers-reduced-motion: no-preference)` 안에만 정의되어 있다.**
따라서 감소 선호 환경에서는 다섯 가지가 **전부 정지**하고 최종 상태가 정적으로 남는다(FR-038).

| 애니메이션 | 감소 선호 시 |
|---|---|
| Aurora `drift` | 정지. 그라데이션은 그대로 보인다 |
| 질문 카드 `floaty` | 정지. 카드 위치·내용 동일 |
| 답변 카드 `floaty` | 정지. 카드 위치·내용 동일 |
| 스피너 `sp` | 회전 정지. **`불러오는 중입니다.` 텍스트가 로딩을 알린다** |
| 스켈레톤 `pulse` | 깜빡임 정지. 회색 바는 그대로 자리를 지킨다 |

- **정보가 애니메이션에만 담기지 않는다.** 로딩·저장 중은 텍스트가 알리고, 질문→답변 흐름은 정적 카드와
  연결선·레이블이 알린다.
- 애니메이션을 새로 추가할 때는 **반드시 같은 미디어 쿼리 안에** 넣는다. 규칙 밖에 정의된 애니메이션이
  하나라도 생기면 위반이다.
- 진입 애니메이션·스크롤 트리거 효과는 확정본에 없다. 추가하지 않는다.

스크롤 잠금 연출 · 스크롤 패럴랙스 · 마우스 추적.

### 23.3 가독성·접근성 위반
어두운 배경 위 흐린 회색 본문 · 그라데이션 위에 직접 얹은 본문(Scrim 없이) ·
색만으로 구분되는 상태 · 아이콘만 있는 상태 표시 · 라벨 없이 플레이스홀더만 있는 입력창 ·
포커스 표시 제거 또는 hover로 대체 · 44px 미만 터치 대상 · 모바일 16px 미만 입력 글자 ·
`--divider`를 입력창 테두리로 사용.

### 23.4 구조 위반
메인에 질문 목록/내용 노출 · **회원 화면에 비활성 상태로 띄운 답변 입력창** ·
세 화면이 서로 다른 헤더·버튼·배지·여백을 쓰는 구성 · 모달로 삭제 확인 ·
역할 전용 화면 신설 · 그림자만으로 만든 카드 경계.

## 24. 구현 후 시각 검증 항목

각 항목은 **통과/실패를 기록**한다. 하나라도 실패하면 완료로 보지 않는다(헌장 원칙 XIII).

### A. 명세 정합성 (원칙 IV·XII)
- [ ] 화면의 모든 요소가 FR 하나 이상에 대응한다.
- [ ] 23.1의 금지 요소가 하나도 없다.
- [ ] 역할 차이가 **요소의 존재/부재**로 구현되었다(비활성으로 암시하지 않음).
- [ ] 답변 후 회원 수정·삭제 버튼이 없고 안내 문구가 나온다(FR-012).
- [ ] 삭제 시 확인 단계를 거친다(FR-011).

### B. 정보 구조와 일관성 (원칙 V)
- [ ] 세 화면이 같은 헤더 컴포넌트를 쓴다.
- [ ] 상태 용어가 `답변 대기`·`답변 완료` 두 가지로 전 화면 동일하다.
- [ ] 되돌아가기 문구가 `← 목록으로 돌아가기` 하나로 통일되어 있다.
- [ ] 버튼·입력·카드·배지가 19절 규격과 일치한다.

### C. 시각 효과와 성능 (원칙 VI)
- [ ] Hero 효과를 전부 제거해도 제목·보조 문구·CTA·3단계가 동일하게 읽힌다(FR-035).
- [ ] 움직이는 요소가 5종(10.5절 표)을 넘지 않고 값이 표와 같다.
- [ ] 배경 이미지·동영상·Lottie를 쓰지 않았다.
- [ ] 제목·CTA가 배경 효과보다 먼저 표시된다.
- [ ] Scrim 레이어가 존재하고 제거되지 않았다.

### D. 대비와 접근성 (원칙 VI·VIII·IX)
- [ ] **17절의 모든 대비를 다시 계산해 표로 기록**했다. 육안 확인은 근거가 아니다.
- [ ] 본문 4.5:1, 큰 글자 3:1, 비텍스트 3:1을 여유 있게 넘는다.
- [ ] **어두운 표면의 포커스 링이 `--focusDark`로 분리**되었다.
- [ ] 화면을 회색조로 변환해도 모든 상태가 구분된다.
- [ ] 주요 행동 8종을 키보드만으로 완료했다(SC-008).
- [ ] 자동 검사 도구(axe 등) 결과에 위반이 없다.

### E. 반응형 (원칙 X)
- [ ] 390px에서 가로 스크롤이 없다.
- [ ] 390px에서 질문 등록과 답변 확인을 끝까지 완료했다(SC-007).
- [ ] 모바일 목록이 카드 형태이고 상태가 제목보다 먼저 온다.
- [ ] 터치 대상이 44×44px 이상이다.
- [ ] 접이식 메뉴 없이 내비게이션이 성립한다.

### F. 상태 (FR-029~FR-032)
- [ ] 로딩·빈 목록·오류·권한 없음·저장 중이 모두 텍스트로 표시된다.
- [ ] 로딩 스켈레톤 행 높이가 실제 행(58px)과 같아 레이아웃이 튀지 않는다.
- [ ] 빈 목록·오류에서 필터 건수가 표시되지 않는다.
- [ ] 저장 중에 중복 제출이 차단된다.
- [ ] 오류 문구에 내부 예외가 노출되지 않는다.

### G. 모션 (원칙 VII)
- [ ] 모션 감소 설정을 켠 상태로 세 화면을 점검한 기록이 있다.
- [ ] 애니메이션을 정의한 모든 규칙이 `prefers-reduced-motion: no-preference` 안에 있다.
- [ ] 모션 정지 상태에서 로딩·저장 중을 텍스트로 알 수 있다.

### H. 단순성 (원칙 XI)
- [ ] 메인의 세로 구획이 5개 이하이다(Hero·전환·흐름·마무리·푸터).
- [ ] 컴포넌트가 필요한 만큼만 정의되었다: 버튼 5종, 입력 2종, 카드 2종(밝은/어두운), 배지 1종,
      상태 박스 1종, 목록 행 1종, 모바일 카드 1종.
- [ ] 같은 목적의 컴포넌트가 두 벌 존재하지 않는다.
